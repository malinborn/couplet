# mdmini 1.3.0

**Four themes, a renderer out of beta, and a cross for everyone who cannot unsee the tick.**

```
brew update && brew upgrade --cask mdmini
```

---

## Live Render is the default, and no longer a beta

The mode that hides markdown syntax outright is what you get on launch now, including if you never opted in.

All three engines are still there under `View → Editor Engine`, spelled `Raw`, `Preview` and `Live Render`. The word "Live" in "Live Preview" only ever existed to contrast with the beta, and there is nothing left to contrast with.

Someone sitting in Raw stays in Raw. That is a decision to look at the source, not a rendering preference to overrule — but the next `⌘E` brings them into Live Render.

## ⌘E stopped rotating through renderers

Live Render and Preview are two answers to "how should the markup look", and you pick between them once, in a submenu. `⌘E` asks something else entirely — "show me the source" — so it now flips between Raw and whichever renderer you chose, and lands back where you left.

The "Include Live Render in ⌘E" switch that used to make it a three-way rotation is gone.

## Two new themes, and neither is a port

**Blueprint** is a cyanotype. White on deep blue, because white there is not an accent but unexposed paper — and red is reserved for what you change: the caret, the checkbox, struck-through text. Its light half is tracing paper with a blue pencil.

**Phosphor** is a terminal from before colour. P1 green on black glass, amber as the only second hue (the other phosphor, from the terminal next to it), and monospace in the prose itself. Its light half is a fanfold printout.

## The Theme menu is three groups, not a list

Family (Classic, Aurora, Blueprint, Phosphor), half (Light, Dark), and **Follow System** as a checkbox.

"System" used to be a fifth mutually exclusive option, which is the one thing it is not: it decides the half, and it has nothing to say about which family you like. Tick it and the theme follows your Mac from day into night without leaving the family you chose.

"Default" is now called **Classic** — the name it has had in the code since it was written.

## A ticked task reads as done

Greyed and struck through, while bold stays bold, italic stays italic and a link keeps its underline. Only the colour is taken over.

A wrapped item stays greyed across its continuation lines; an unfinished child of a finished parent does not. The range follows the item, not the line.

In the Aurora themes the grey is a gradient. In Blueprint the line is drawn in that theme's red pencil while the text stays muted: crossed off, not deleted.

## One menu item where four documents used to be

`AI → Teach Your AI mdmini`.

"Getting Started", "Connect via CLI", "Connect via MCP" and "Teach your AI" each explained their own part and left the assembly to you, so setting this up meant stitching a configuration out of four texts.

The document now hands over a prompt instead. Your agent registers md-mini over MCP, writes itself a skill on how to use it well, and adds a short note to its own config about when to reach for it — knowledge in the skill, which loads only when needed, and only the trigger in the config, which is read on every run. It is told plainly to prefer MCP and fall back to the `mdmini` CLI when MCP is unavailable.

A second prompt in the same document does the skill only, for anyone who would rather their main config stayed untouched.

## OCD Alignment

The tick in a checked box sits a hair off centre. That is not sloppiness: `✓` is not a symmetrical glyph, so it never looks centred anywhere, whatever you do to it.

If that hair is going to follow you around all day, `View → OCD Alignment` replaces it with a cross drawn as two strokes rotated around one point — symmetrical by construction, with nothing left to drift.

We like the tick. We also know how it is.

## Fixes

- **The table header stopped ignoring the theme.** Its gradient was hardcoded in two variants, picked by whether the theme's name ended in "light" — so Phosphor got a lilac header on green paper. It is a theme variable now, with the old values as the default, so the themes that never asked look exactly as they did.
- **A checkbox in the menu works with two windows open.** A menu event is broadcast to every window, and each applied it to its own copy of the setting. Harmless for a radio item, where N windows set the same value; not for a toggle, where N windows flip it N times. The event now carries the value rather than the instruction to flip.
- **Zoom In has a key again.** It was declared as `⌘Plus`, and accelerators are parsed by key code, where `Plus` is not one — the item simply had no shortcut. It is `⌘=` now, next to `⌘−`.
- **Open on an in-document link does something.** In Live Render's link inspector it used to do nothing at all for a `#heading` target; it jumps to the heading.
- **The welcome page is about this version.** It was still describing 1.0 and a menu that no longer exists.
