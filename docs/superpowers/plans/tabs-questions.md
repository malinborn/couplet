# Вкладки — вопросы на утро

*Ночь 2026-09-24 → 25. Сессия «couplet tabs implementation». По каждому вопросу принято обратимое решение по умолчанию, работа не останавливалась.*

## Q1. Нужен ли отдельный пункт меню «Открыть N окон прошлой сессии», кроме ⌘⇧T?
- **Контекст:** план 01, задача 7 (`src-tauri/src/menu.rs`, `src-tauri/src/closed.rs`). По спеке §6 ⌘⇧T возвращает последнее закрытое, а сессию восстанавливает, только «пока ничего не закрыто». Значит, после первого же ⌘W прошлая сессия доступна только если по одному переоткрыть всё закрытое.
- **Что я сделал пока:** оставил один пункт с ⌘⇧T, как в спеке. В тосте о сессии вместо подсказки «нажмите ⇧⌘T» поставил кнопку «Восстановить» (команда `restore_session`): так сессию можно вернуть, пока тост на экране. Решение обратимое, правка в одном Svelte-файле.
- **Альтернативы:**
  1. Как в Safari: отдельный пункт «Открыть N окон прошлой сессии» без клавиши, включён, пока сессия не восстановлена; ⌘⇧T — только закрытое. Около 30 строк в `menu.rs` и обработчике, логика пункта упрощается.
  2. Оставить как есть: только кнопка в тосте. Закрыл тост — сессию можно вернуть только через ⌘⇧T по одному окну.

## Q3. Откат на старую версию удаляет несохранённые черновики untitled, созданные новой версией. Защищаться?
- **Контекст:** план 01 задача 5 и план 02 задача 5 (`src-tauri/src/session.rs`). Новые черновики называются `untitled-<tab_id>.md`. Старая сборка при уборке удаляет все `untitled-*.md`, на которые не ссылается её `session.json`, а о `session-v2.json` она не знает. После отката несохранённые черновики, созданные новой версией, пропадут при первой уборке. Сами JSON-файлы сессии при откате остаются, как были.
- **Что я сделал пока:** ничего. Сейчас это касается только чередования dev-сборок (`main` и `feat/tabs` пишут в один `md-mini-dev/`). Для релиза это значит «откат с вкладок на 1.x теряет несохранённые черновики».
- **Альтернативы:**
  1. Новый префикс для черновиков (например, `draft-<tab_id>.md`), который старая уборка не трогает; новая понимает оба. ~10 строк, но старая версия этих черновиков не покажет (и не удалит).
  2. Оставить как есть и написать в заметках к релизу: «перед откатом сохраните черновики».
  3. Выпустить в релизе фундамента (A) уборку, которая не трогает незнакомые имена, — тогда откат с B на A безопасен.

## Q2. Ручной тест на 2 минуты перед планом 05: доставляет ли WKWebView pointer-события за краем окна?
- **Контекст:** спека §6 «Пространственные операции», §13 п. 2; дорожная карта «Перед планом 05». Мыши у ночной сессии нет, поэтому проверить руками нельзя. Тест лежит в спайк-ветке `worktree-agent-a5a10b8e48a0bf525`, файл `docs/dnd-spike-manual-test.md`.
- **Что я сделал пока:** план 05 (если до него дойдёт ночью) строится с запасным путём — во время drag опрашивается `cursor_position` из Rust, так что механизм работает при любом ответе. Если pointer-события за краем окна приходят, опрос можно убрать.
- **Альтернативы:**
  1. Только события (если тест зелёный) — проще, без таймера.
  2. Только опрос `cursor_position` — одинаково на всех версиях WebKit, чуть больше кода.
  3. Оба (сделано по умолчанию) — события, а опрос как страховка.
