## Релизы

- **Релиз A — фундамент (01).** Можно выпускать сразу: это чистая починка без видимых новшеств. Должен выйти **до ребрендинга**, потому что Recent уходит из localStorage, привязанного к identifier.
- **Релиз B — «Вкладки» (02 + 03 + 04 + 05).** Выпускается одним куском: вкладки без дровера неполны, а смену контракта `show` выпускаем **вместе с ребрендингом**, когда MCP всё равно перерегистрируют и старые процессы `md-mini mcp` уходят. Session v2 и миграцию каталога данных ребрендинга не выпускаем в одном релизе.
- Если 05 затянется, релиз B может выйти с командой «В новое окно» из выделения вместо перетаскивания, а жест догонит.

## Перед планом 05

Ручной тест на 2 минуты: доставляет ли WKWebView pointer-события за краем окна при pointer capture. Лежит в `docs/dnd-spike-manual-test.md` ветки `worktree-agent-a5a10b8e48a0bf525`. От результата зависит механизм: события или опрос `cursor_position`.

## Как исполнять

Каждый план — через `superpowers:subagent-driven-development`: свежий агент на задачу, ревью между задачами, `code-reviewer` в конце плана. Проверка визуала — `npm run dev` + Playwright и `npm run dev:app`, установленный couplet не трогаем.
