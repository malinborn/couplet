## Как работать
- **Субагенты — строго по одному за раз.** Реализацию веди через `superpowers:subagent-driven-development`: свежий субагент на задачу, ревью между задачами. Никогда не запускай двух субагентов параллельно: ни несколько Agent-вызовов в одном сообщении, ни Workflow, ни agent teams. Сам пиши минимум кода: ты оркестратор и ревьюер.
- **Соблюдай план.** Задачи идут в порядке плана, с его тестами. Если план расходится с кодом (строки уехали, функция называется иначе), подстрой шаг под реальный код, не меняя смысла задачи, и отметь это в ночном отчёте. Если план расходится со спекой или с контрактами дорожной карты, права спека, затем дорожная карта. Спроси архитектора (ниже).
- **Порядок работ:**
  1. Worktree через `EnterWorktree` (имя `stash-impl`), затем `git fetch && git merge origin/worktree-shelf-design`.
  2. **Этап 01 — страховка черновиков.** Ветка `fix/draft-safety` от этого состояния. Выполни план `…-stash-01-safety-net.md` целиком. В конце — `code-reviewer` по диффу, исправить найденное, запушить ветку, открыть **draft PR** в main. Релиз не выпускать: его сделает Max.
  3. **Этапы 02 → 03 → 04 → 05 → 06 → 07 по очереди.** Ветка `feat/stash` от `fix/draft-safety`. Для каждого этапа:
     1. отправь архитектору короткое «начинаю этап N»;
     2. исполни план;
     3. прогони `code-reviewer` по диффу этапа, исправь найденное, закоммить, запушь;
     4. допиши итог этапа в ночной отчёт и отправь архитектору короткий итог.

     В конце — один **draft PR** `feat/stash` в main (он включает и этап 01; в описании сошлись на PR этапа 01).
  4. **Если ночи не хватит:** приоритет — этапы 01–03. После них текст Max в безопасности даже без дровера. Останавливайся только на границе этапа, никогда посреди этапа.
- **Проверки.** После каждой задачи — тесты, указанные в плане. В конце каждого этапа: `npx vitest run --dir src`, `CARGO_TARGET_DIR=~/.cargo/stash-impl-target cargo test --manifest-path src-tauri/Cargo.toml`, `cargo clippy` (новых предупреждений относительно базы на начало этапа быть не должно), `npm run check`, `npm run check:x86`. Визуал этапов 04 и 06 сверяй с макетом: `npm run dev` + Playwright (`chromium.launch({ channel: 'chrome' })`, свои скрипты, не общий MCP-браузер) и `npm run dev:app -- --features mcp-bridge`. Скриншоты — в `docs/superpowers/plans/night-shots/stash/`.
- **Другие сессии.** Параллельно по couplet могут работать другие сессии и мержить в main. Ты не мержишь main сам. Если к концу ночи `feat/stash` конфликтует с `origin/main`, опиши конфликт в отчёте, а не решай его силой.

## Сборка и тестирование — собирать и гонять dev-приложение МОЖНО и НУЖНО
Функционала много. Проверяй его в настоящем приложении, а не только юнит-тестами. Всё ниже работает под dev-идентификатором `pro.couplet.dev` (`couplet-dev`) со своими данными, сокетами и single-instance и не мешает установленному couplet у Max. Всегда задавай свой `CARGO_TARGET_DIR=~/.cargo/stash-impl-target`.
- **UI в браузере:** `npm run dev` + Playwright. Сюда относятся дроверы, зона сброса, фильтр, ширины, сверка с макетом.
- **Живое приложение с Tauri** (окна, IPC, файлы, SQLite): `npm run dev:app`. Управлять им агентом: `npm run dev:app -- --features mcp-bridge` и tauri MCP-инструменты. Сначала прочитай раздел «MCP dev bridge» в CLAUDE.md: там ловушки 0.12.0 (eval без await, синтетические клавиши без `e.code`, text-стратегия в dev).
- **Реальные клавиши (⌃T, ⌃S)** проверяй с окном dev-сборки на переднем плане: фоновый `postToPid` врёт (CLAUDE.md). Никаких System Events.
- **Настоящий бандл** (quit, AppleEvent, обновление версии для этапа 01): `npm run build:dev`, запуск `couplet-dev.app/Contents/MacOS/couplet` прямо из терминала; quit — только `osascript -e 'quit app id "pro.couplet.dev"'`. **В /Applications не устанавливать.**
- **CLI и MCP против dev-сборки — только с явным dev-сокетом и dev-продуктом.** По умолчанию `couplet …` и `couplet mcp` стучатся в боевое приложение Max. Твои собственные MCP-инструменты `couplet` (show/edit/ask) в этой сессии тоже смотрят в боевое приложение: используй их только чтобы показать Max документ, **никогда для тестов**.
