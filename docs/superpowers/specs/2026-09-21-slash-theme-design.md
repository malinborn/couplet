# `/theme` — смена темы из слэш-меню

**Дата:** 2026-09-21
**Статус:** утверждено, к реализации

## Задача

Дать возможность сменить тему прямо из редактора, не уходя в нативное меню
View → Theme. Команда набирается как `/theme`, открывает список из пяти тем
и показывает каждую **вживую**, пока пользователь ходит по списку стрелками.
Enter фиксирует выбор, Esc возвращает исходную тему.

## Почему это не просто «ещё один пункт меню»

Сегодня слэш-меню — чистая вставка блоков. Все 13 элементов `blockTemplates`
только пишут текст в документ, и `apply()` у каждого из них — один
`view.dispatch({changes})`. `/theme` ничего не вставляет: это первая
команда-**действие**, и она меняет состояние, которое живёт вне документа —
глобальную тему приложения.

Отсюда два неочевидных требования, которые и составляют основную цену фичи:

1. **Редактор не должен импортировать стор темы.** `createExtensions()` зовут
   двое: `Editor.svelte` и `site/demos/editor-demo.ts` — демо-карточки на
   лендинге md-mini.com. Прямой импорт стора затянет `localStorage` и
   `matchMedia` на лендинг и даст демо-редактору право перекрашивать страницу.
2. **Тема согласована между окнами.** Нативное меню сегодня меняет тему во
   всех окнах: Rust броадкастит `menu-event` каждому окну (`lib.rs`, ветка
   «Broadcast all other menu events to all windows»). `/theme`, меняющий только
   своё окно, даст два окна с разными темами до перезапуска — а на рестарте
   победит то из них, что последним записало `localStorage`.

## Архитектура

### 1. Второй тип элемента слэш-меню

Новый файл `src/lib/editor/slash-actions.ts`:

```ts
export interface SlashAction {
  /** Суффикс команды: `theme` → `/theme`. */
  id: string;
  /** Подпись в popup. */
  label: string;
  /** Правая колонка popup. */
  detail: string;
  /** Что сделать вместо вставки текста. Набранный `/theme` уже удалён. */
  run(view: EditorView): void;
}
```

`slashCommands()` получает сигнатуру `slashCommands(actions: SlashAction[] = [])`
и отдаёт два вида опций через `Completion.section`:

| Секция  | Источник         | `apply`                                      |
|---------|------------------|----------------------------------------------|
| Blocks  | `blockTemplates` | вставляет `tpl.insert` (как сейчас)          |
| Actions | `actions`        | удаляет набранный текст, затем зовёт `run()` |

Массив по умолчанию пуст, поэтому лендинг получает ровно сегодняшнее поведение.

### 2. Инъекция вместо импорта

`setup.ts`:

```ts
export interface EditorDeps {
  themeControl?: ThemeControl;
}
export function createExtensions(deps: EditorDeps = {}): Extension[]
```

Если `deps.themeControl` передан — в `slashCommands()` уходит
`[themeAction(deps.themeControl)]`; иначе список экшенов пуст и `/theme`
в меню не появляется.

Контракт (`src/lib/editor/slash-theme.ts`):

```ts
export interface ThemeControl {
  /** Текущий preference — для отметки «● текущая» в списке. */
  readonly current: ThemeSetting;
  /** Показать тему, ничего не сохраняя. `null` снимает превью. */
  preview(theme: ThemeSetting | null): void;
  /** Зафиксировать: записать, поправить нативное меню, разослать по окнам. */
  commit(theme: ThemeSetting): void;
}
```

`Editor.svelte` получает `themeControl?: ThemeControl` пропом и передаёт его
в `createExtensions()`. `App.svelte` строит объект над своим `theme` стором.
Редактор про Svelte по-прежнему ничего не знает.

### 3. Превью идёт через стор, а не через DOM

В `createThemeStore()` добавляется `previewOverride = $state<ThemeSetting | null>(null)`,
и `resolved` считается от `previewOverride ?? preference`. Существующий
`$effect`, ставящий `data-theme` на `documentElement`, не меняется — он просто
начинает видеть другое значение.

Прямая запись атрибута в обход стора отвергнута: любой повторный прогон
эффекта (например, смена системной темы во время открытого пикера) вернул бы
атрибут к сохранённому значению и превью молча слетело бы.

Превью **не** пишет в `localStorage`, **не** зовёт `syncThemeMenu` и **не**
уходит в другие окна. Всё это делает только `commit`.

### 4. Двухступенчатое меню

**Шаг 1.** `/theme` — обычная опция в секции Actions. Её `apply` удаляет
набранный текст (`from`…`to`), диспатчит `StateEffect` `openThemePicker`
с якорем = позицией каретки и зовёт `startCompletion(view)`.

**Шаг 2.** Второй источник автокомплита, зарегистрированный тем же
`EditorState.languageData`, активен только когда `themePickerField` поднято.
Отдаёт пять опций:

| Опция        | `ThemeSetting` |
|--------------|----------------|
| Light        | `light`        |
| Dark         | `dark`         |
| Aurora Light | `aurora-light` |
| Aurora Dark  | `aurora-dark`  |
| System       | `system`       |

У опции, совпадающей с `themeControl.current`, в `detail` добавляется
`● текущая`. Все пять получают `type: 'md-theme'`.

Это **отдельный источник**, а не расширение регулярки первого: текущая
`matchBefore(/(?:^|\n)\s*\/\w*/)` не матчит ни пробел, ни дефис, так что
`/theme aurora-light` она бы не поймала в принципе.

**Свотчи.** `autocompletion({ addToOptions: [...] })` получает рендерер,
срабатывающий только на `completion.type === 'md-theme'`: два кружка слева
(фон темы и её акцент), взятые из CSS-переменных соответствующей темы.
Гейт по типу обязателен — `addToOptions` глобален и иначе полез бы в
completion-ы языка.

### 5. Живое превью и откат

`updateListener` следит за `selectedCompletion(update.state)`, пока пикер
активен, и на каждое изменение зовёт `themeControl.preview(theme)`.

| Событие                             | Что происходит                                               |
|-------------------------------------|--------------------------------------------------------------|
| Стрелка вверх/вниз, наведение мышью | `preview(theme)` — окно перекрашивается сразу                |
| Enter / клик по опции               | `commit(theme)`, `preview(null)`, поле опускается            |
| Esc, клик мимо, потеря фокуса       | `preview(null)`, текст после якоря удаляется, поле опускается |

Отмена детектируется так: поле поднято, `completionStatus(state)` стал `null`,
а коммита не было. Текст, который пользователь успел набрать после открытия
пикера (фильтруя список), удаляется по диапазону «якорь → каретка» — якорь
хранится в самом `themePickerField`.

### 6. Синхронизация окон

Новая Tauri-команда `broadcast_theme(preference: String)` в `commands.rs`:
эмитит `menu-event` с соответствующим id (`theme_light`, `theme_dark`,
`theme_aurora_light`, `theme_aurora_dark`, `theme_system`) во все окна —
ровно тот путь, которым уже ходит нативное меню, так что обработчик в
`App.svelte` не меняется вообще.

Окно-инициатор тоже получит событие и присвоит то же самое значение; это
идемпотентно и совпадает с тем, как сегодня ведёт себя клик по меню.

В браузерном `npm run dev` `invoke` падает молча (как у `syncThemeMenu`), и
локальная тема всё равно применяется — иначе фичу нельзя было бы проверить
в браузере.

## Тестирование

**Vitest:**

- источник слэш-команд отдаёт секцию Actions, когда `actions` непуст, и не
  отдаёт, когда пуст (лендинг);
- `apply` у `/theme` удаляет набранный текст и поднимает `themePickerField`;
- второй источник молчит при опущенном поле и отдаёт пять опций при поднятом;
- отметка `● текущая` стоит ровно на `themeControl.current`;
- фейковый `ThemeControl`: `preview → commit` оставляет тему,
  `preview → abort` возвращает `null`.

**Браузер (`npm run dev` + Playwright):**

- `/theme` + Enter открывает список из пяти тем;
- стрелка вниз меняет `data-theme` на `documentElement` без записи в
  `localStorage`;
- Enter фиксирует: `data-theme` и `localStorage` совпадают;
- Esc возвращает исходную тему и не оставляет мусора в документе.

## Что сознательно не делается

- Другие команды-действия (`/zoom`, `/raw`, `/export`). Категория Actions
  вводится, но заполняется одним `/theme`; вторая команда — это добавление
  элемента в массив, не рефакторинг.
- Пользовательские темы, импорт цветовых схем. Список фиксирован пятью
  существующими значениями `ThemeSetting`.
- Превью темы в других окнах, пока пикер открыт. Превью локально по
  построению; разъезжаются окна только на время открытого popup.
