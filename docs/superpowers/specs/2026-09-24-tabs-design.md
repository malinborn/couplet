# Вкладки и окна в couplet — дизайн

*2026-09-24 · статус: решения владельца из `docs/superpowers/plans/tabs-questions.md` внесены, спека сверена с `feat/tabs` (планы 01–05) · заменяет рекомендацию «AI-стол» из `docs/investigations/2026-09-23-tabs-options.md` (та ветка отклонена, см. §12)**

> **Эталон визуала и опыта — `docs/investigations/2026-09-24-tabs-mockup/drawer.html`** (утверждён владельцем 2026-09-24, git-тег `tabs-mockup-approved`). Реализация стремится к нему: хлястик, дровер, подсказки, фильтр, компактный вид, выделение, перетаскивание. Если спека и макет расходятся в визуале — прав макет; в поведении — спека, а расхождение исправляется в обоих.

## 1. Зачем

Владелец хочет вкладки, но боится Chrome/Sublime: тонны вкладок, которые страшно закрыть и невозможно держать в порядке, забитого экрана и хаоса от ИИ, который открывает файлы сам.

**Принципы:**
1. **Окно — самостоятельное понятие** с номером и проектом, а не «рамка вокруг файла». Раскладку задают явно: человек или ИИ говорит, в какое окно.
2. **ИИ — желанный гость.** У ИИ те же действия, что у человека: открыть в окне, в фоне или в фокусе, закрыть, узнать, какие окна есть. С разрастанием мы боремся не изоляцией ИИ, а его гигиеной (короткий показ с вопросом «закрыть или оставить») и инструментами человека.
3. **Порядок достигается сортировкой и поиском, а не дисциплиной.** Никто не обязан держать вкладки в порядке: список сортируется одной клавишей, нужная вкладка находится набором пары букв, а карточка с текстом сама напоминает, что это было.
4. **На экране по умолчанию ничего нет.** Верхней полосы вкладок нет, есть только хлястик на краю окна.
5. **Закрывать дёшево.** Есть крестик, ⌘-клик и закрытие группы. Файлы остаются на диске, а ⌘⇧T возвращает закрытое.

## 2. Понятия

| Понятие | Что это |
|---|---|
| **Окно** | Номер `#N` (1–99) и проект, содержит упорядоченный список вкладок, активна одна вкладка |
| **Вкладка** | Файл на диске или untitled-буфер. Один файл открыт не больше чем в одной вкладке во всём приложении (dedup по пути) |
| **Проект окна** | Git toplevel (`git rev-parse --show-toplevel`) файла, которым окно открыто. **Worktree — отдельный проект** (у каждого свой CLAUDE.md). Для файла вне git — его каталог |
| **Непросмотренная вкладка** | Её открыл ИИ, и человек её ещё не активировал. Она переливается ИИ-градиентом |

## 3. Номера окон

- Новое окно получает **наименьший свободный** номер из 1–99: открыто #1, открыли #2, закрыли #1 → следующее окно #1, за ним #3. Ничего не хранится. Цена: агент со старым `-t 7` может попасть в новое окно, которое заняло 7, — принято.
- Номер стабилен между перезапусками: окно восстанавливается сессией вместе со своим номером.
- **Номер можно сменить:** при открытом дровере двойной клик по `#N` на хлястике → поле ввода (цифры, 1–99, текущий номер выделен). Enter — применить, Esc или уход фокуса — отмена. Номер живого окна занят → поле трясётся, тост «Номер #N занят»; неверное значение тоже трясёт, ничего не меняется. Новый номер сразу в заголовке, на хлястике, в сессии, в `ls` и для `-t N`.
- **Отображение:** в заголовке `README.md — #7` (вместо `— md-mini`), на хлястике `#7`. Решётка отличает номер окна от номера вкладки (⌘1…⌘9). В CLI решётки нет: `-t 7`.
- Совпадение номера точное, префиксы не нужны.
- **Мёртвый номер** даёт ошибку со списком живых окон, у каждого до трёх файлов:
  ```
  couplet: окна #12 нет. Открыты:
    #3  md-mini            README.md, CLAUDE.md, tabs-design.md …
    #7  infra              deploy-plan.md, incident-2026-09-21.md
  ```

## 4. CLI

Имена `couplet` / `coup` / `mdmini` (см. ребрендинг).

| Команда | Человек (`CLAUDECODE` не задан) | Агент (`CLAUDECODE=1`) |
|---|---|---|
| `coup file.md` | новое окно, привязанное к проекту файла; файл открыт → фокус туда | маршрутизация §5, вкладка **в фоне** |
| `coup a.md b.md` | новое окно, файлы как вкладки | маршрутизация, вкладки в фоне |
| `coup file.md -t 7` | вкладка в окне #7, в фокусе | вкладка в окне #7, в фоне |
| `coup file.md -t 7 -b` | вкладка в окне #7, **в фоне**: хлястик переливается, фокус остаётся, где был | то же |
| `coup file.md -f` | — (у человека фокус и так по умолчанию) | вкладка **в фокусе** (как MCP `focus: true`) |
| `coup ls` | список окон: номер, проект, вкладки | то же, есть `--json` |
| `coup close file.md` | закрыть вкладку | закрыть вкладку (правила §8) |

**Флаги фокуса** `-b` / `--background` и `-f` / `--focus` переопределяют умолчание в любой команде открытия, с `-t` и без. Человеческий `coup file.md -b` без `-t` идёт по маршрутизации §5, шаги 2–4. Если окна проекта ещё нет, новое окно создаётся без активации приложения: открывать пустое окно на весь экран «в фоне» бессмысленно.

**Finder** (двойной клик, «Открыть с помощью», сброс на иконку) идёт по маршрутизации §5, шаги 2–4: уже открытый файл получает фокус; иначе файл открывается вкладкой в окне своего проекта (если таких несколько — в последнем, что было в фокусе); иначе его берёт нетронутый `main` (без проекта и без файловой вкладки); иначе новое окно. Окно выходит вперёд, как при любом открытии человеком (tabs-questions Q4).

## 5. ИИ: маршрутизация и контракт

Открытие файла агентом (`show`, `edit`, `ask`, `coup file`) ищет окно в таком порядке:
1. Передан `window_binding` / `-t` → это окно. Мёртвый номер → ошибка §3.
2. Файл уже открыт → его вкладка.
3. Есть окно, чей проект совпадает с проектом файла → новая вкладка там. Если таких окон несколько, берётся последнее, которое было в фокусе.
4. Иначе → новое окно, привязанное к этому проекту.

**MCP `show`:**
- `path`, `line` / `find` — как сейчас;
- **`window_binding?: number`**;
- **`focus?: boolean`** (по умолчанию `true`): `true` делает вкладку активной и выводит окно вперёд, `false` открывает её в фоне с переливом;
- **`transient?: boolean`** — короткий показ (§7).

Ответ: `{ ok, window: 7, focused: bool }`. Агент переиспользует `window` в следующих вызовах. В описание инструмента добавляется: «Reuse the returned `window`; use `transient` for quick looks».

**Новые инструменты:**
- `close(path)` — закрыть вкладку;
- `windows()` — список окон, проектов и вкладок. Это тот же `coup ls --json`, чтобы агент мог выбрать окно.

**`edit`** в фоновую вкладку применяется к её закешированному состоянию, с undo и подсветкой при активации. Не открытый нигде файл открывается по маршрутизации в фоне.

**`ask`** в фоновую вкладку: вкладка переливается, вопрос появляется, когда её открывают. Таймаут считается от запроса; вопрос, чей срок вышел, при открытии вкладки не показывается (план 04, D6). Если `ask` пришлось создать новое окно, это окно выходит вперёд и приложение активируется — кроме случая, когда человек печатает (tabs-questions Q7).

**Не отнимать клавиатуру.** «Человек печатает» считается на всё приложение: пока хоть в одном окне был набор за последние 2 с (окно отмечается в Rust через `note_typing`), любая команда агента уходит в фон, отвечает `focused: false`, и ни одно окно не выходит вперёд (tabs-questions Q10).

**Совместимость:** работающие процессы `md-mini mcp` пересериализуют ответ и выбрасывают незнакомые поля (`mcp_server.rs:467`). До перезапуска сессий агенты не увидят `window`, поэтому смену контракта выпускаем вместе с ребрендингом, когда MCP всё равно перерегистрируют.

## 6. Интерфейс

### Хлястик
- **Небольшой язычок у левого края окна**, не вся кромка: вытянутая трапеция, как выступ на картонной папке. Остальной край окна свободен. Под язычком — существующая кнопка ИИ.
- Весь текст на нём **вертикальный** (читается снизу вверх): номер окна `#7`, число вкладок, тонкая черта, подсказка `⌘J`. Это единственное место, где показана клавиша дровера.
- Хлястик следует теме: фон, рамка и приглушённый текст берутся из токенов темы, **номер окна — акцентным цветом темы**; число вкладок и `⌘J` приглушены.
- **Перелив:** медленный ИИ-градиент `#f590e1 → #72dcfd`, пока в окне есть непросмотренные вкладки. Открыл вкладку — она перестала переливаться. Не осталось таких вкладок — перестал и хлястик. При `prefers-reduced-motion` градиент статичный.

### Дровер
- **Открытие:** наведение на хлястик с задержкой ~200 мс или **⌘J**. Закрывается тем же ⌘J, Esc или уходом курсора.
- **Открытый дровер забирает клавиши и фокус** — любой, открытый наведением тоже: фокус уходит в дровер, печатные клавиши идут в фильтр, Esc и стрелки — дроверу. При закрытии фокус возвращается в редактор с прежней кареткой. Эвристик «последний ввод был в редакторе» и «удержание курсора» нет: случайное наведение во время набора уводит буквы в фильтр — осознанная цена простоты (tabs-questions Q5).
- **Шапка** закреплена и занимает минимум места: `Окно #7 · 6 вкладок` (число вкладок сразу после номера окна). Подсказки клавиши в шапке нет: она на хлястике. Справа на той же строке — тихая серая подсказка «⌕ печатайте для поиска», посередине «⇧ — выделить» того же цвета и размера (прячется первой, если не хватает места). Все три элемента строки стоят на одной базовой линии. Пока поиск активен, обе подсказки скрыты. Под ней в одну строку сортировки: `Разложить: открытие ⌘L · просмотр ⌘R · ✦ ИИ ⌘U`.
- **Фильтр набором.** При открытом дровере любая печатная клавиша без модификаторов сразу начинает поиск, никуда кликать не надо. Запрос виден строкой вверху списка.
  - Ищем и по имени файла, и по содержимому. **Совпадения в имени идут первыми** (сначала по началу имени, потом по подстроке), за ними совпадения в тексте.
  - Совпавшее подсвечивается. Если совпал только текст, в превью карточки вместо первых строк показывается строка с совпадением.
  - ↑/↓ двигают выбор, Enter открывает верхний результат, Backspace правит запрос. Первый Esc сбрасывает запрос, второй закрывает дровер. Если ничего не нашлось — тихое «Ничего не найдено».
  - Поиск по содержимому идёт по тексту открытых вкладок, фоновые берём с диска.
- **Карточка вкладки:** имя файла, серым «проект/ветка», 2–3 строки текста. У активной вкладки подсветка, у первых девяти подсказки ⌘1…⌘9. Непросмотренные переливаются.
- **Компактный вид — View → Tabs → Compact** (галочка в меню, по умолчанию выключена). Карточка в одну строку: имя и серым «проект/ветка» на той же строке (длинное обрезается многоточием). Под ней только **первая непустая строка** файла; если непустых строк нет, ничего. ⌘N-подсказка и крестик остаются.
- **Удержание курсора** на карточке ~600 мс: она плавно расширяется и показывает больше текста, как документ, который вытаскивают из папки.
- **Закрытие:** крестик на карточке и ⌘-клик.
- **Порядок:** карточки перетаскиваются, ⌘1…⌘9 идут по текущему порядку.
- **Сортировки** — разовая перестановка, не режим («упорядочить по», как в Finder). После неё можно снова двигать руками. Кнопки в шапке дровера и хоткеи, которые работают только при открытом дровере:
  - ⌘L — по дате открытия вкладки, новые сверху («Latest»);
  - ⌘R — по последнему просмотру;
  - ⌘U — сначала непросмотренное от ИИ.

  Голые буквы уходят в фильтр, поэтому у сортировок ⌘. ⌘0, ⌘O, ⌘E, ⌘N, ⌘S, ⌘W, ⌘F, ⌘A заняты нативным меню и в webview не доходят.
- **Выделение** (логика приложений владельца, намеренно не как в Finder):
  - ⇧+клик добавляет карточку в выделение или убирает из него;
  - ⇧ + зажатие и протяжка переключает выделение каждой карточки, над которой прошёл курсор;
  - с группой можно: закрыть, вынести в новые окна, перенести в другое окно.
- **Подсказка** внизу дровера, в одну строку: `⇧ клик / протяжка — выделение` · ⌘ клик — закрыть`. Показывается **только пока зажат ⇧**.

### Пространственные операции — карусель окон
Перенос между окнами идёт внутри окна-источника, курсор его не покидает (tabs-questions Q2, план 05; макет `docs/investigations/2026-09-24-tabs-mockup/drawer-carousel.html`).
- Карточку или ⇧-выделение тянут из дровера на страницу → страница размывается, справа встаёт вертикальная карусель миниатюр других окон: **сверху «+ Новое окно»**, дальше окна **по последнему фокусу (MRU)**. Миниатюра — данные, не скриншот: `#N`, проект, ветка, число вкладок, начало активного документа.
- Край карусели сверху/снизу или колесо — листать. Отпустили на окне → вкладки переезжают туда; на «+ Новое окно» → одно новое окно со всей группой. Вернули в дровер → это обычная перестановка. Esc — отмена.
- С клавиатуры — **⌘G** («В окно…», только в открытом дровере) и кнопка «В окно…» в панели выделения: карусель для выделения, иначе для карточки под стрелками, иначе для активной вкладки; ↑/↓ и Enter.
- Переносится всё, кроме истории undo: текст untitled, каретка, метки дровера, короткий показ, вопросы агентов — одним атомарным шагом в Rust (`tab_move`). Перенесённая вкладка сразу становится активной в окне-цели, окно-цель вперёд не выходит; тост «Перенесено в #N · Перейти» исчезает сам через 6 с (tabs-questions Q11).
- Кнопка «В новые окна» в панели выделения — по окну на вкладку, каскадом.
- **Механизм — собственный drag на pointer-событиях, не HTML5 DnD:** нативный обработчик сброса файлов в Tauri (`dragDropEnabled`, на нём работает перетаскивание файлов в окно) перехватывает OS-drag раньше, чем он станет JS-событием (tauri #4168, #14373, #11930).
- **Перетаскивания за край окна** (на другое окно ОС или в пустоту с окном в точке сброса) **в v1 нет** — известный пробел плана 05. Если его сделают, это ещё одна цель для того же `tab_move`.

### Клавиатура
| Клавиша | Действие |
|---|---|
| ⌘T | новая untitled-вкладка |
| ⌘W | закрыть вкладку; последняя вкладка закрывает окно |
| ⌘1…⌘9 | перейти на вкладку N |
| ⌃Tab / ⌃⇧Tab | следующая / предыдущая вкладка по порядку дровера, по кругу (стандарт Safari/Chrome; выбор владельца 2026-09-24) |
| ⌘⇧T | вернуть последнюю закрытую вкладку или окно; только закрытое, сессию не восстанавливает (для неё — пункт File «Открыть окна прошлой сессии», §8) |
| ⌘J | открыть или закрыть дровер (пункт меню, работает из редактора) |
| ⌘M | свернуть окно (стандартный Window → Minimize) |
| буквы | фильтр, только при открытом дровере (как бы он ни открылся) |
| ⌘L / ⌘R / ⌘U | сортировки, только при открытом дровере |
| ⌘G | «В окно…» — карусель окон, только при открытом дровере. Вне дровера ⌘G остаётся «найти далее» редактора |

Клавиши-пункты меню (⌘T, ⌘W, ⌘⇧T, ⌘J, ⌘1…⌘9) добавляются в `menu.rs` и в `native-menu-accelerators.ts`. Клавиши дровера (⌘L/⌘R/⌘U/⌘G) — только webview, в меню их быть не должно: нативный акселератор срабатывает раньше webview (стережёт `drawer-keys.test.ts`). ⌘J свободна и в меню, и в редакторе (⌘⇧J — вставка JSON — отдельное сочетание). ⌘⇧M не подошёл для «В окно…»: он занят «Comment on Selection».

## 7. Короткий показ (`transient`)

- `show(..., transient: true)` добавляет к вкладке карточку «Закрыть / Оставить».
- Ответ обрабатывается **локально**: агента не ждём, в очередь ничего не кладём, возвращаться к ИИ не нужно. «Закрыть» закрывает вкладку (её можно вернуть через ⌘⇧T), «Оставить» превращает вкладку в обычную.
- **Проигнорировано** значит: вкладку просмотрели, а на вопрос не ответили в течение часа. Непросмотренная вкладка сама не закрывается никогда, иначе получится «чёрная дыра».
- Что делать с проигнорированной, задаётся радиопунктами в меню **File**: «Короткие показы без ответа через час: ● Оставить ○ Закрыть». По умолчанию «Оставить».
- **Короткий показ переживает перезапуск:** флаг и время первого просмотра сохраняются в `session-v2.json` (serde default, без смены версии), час продолжает считаться от первого просмотра до перезапуска. Показ, чей час вышел, пока приложение было закрыто, на первом тике закрывается или остаётся по политике из меню — только фоновый, активный никогда (tabs-questions Q8).

## 8. Закрытие и untitled

- ⌘T создаёт untitled. **⌘W на untitled закрывает её и теряет текст — это фича.** Закрытие группы человеком работает так же.
- **ИИ (`close`) и таймаут `transient` untitled с текстом не закрывают никогда.**
- Сохранённые файлы закрываются без потерь (автосейв). Стек «недавно закрытые» хранится в Rust, ⌘⇧T возвращает вкладку вместе с позицией — и только закрытое.
- **Прошлая сессия** возвращается отдельным пунктом **File → «Открыть окна прошлой сессии»**, как в Safari: без клавиши, включён, пока прошлая сессия не восстановлена. Кнопка «Восстановить» в тосте о сессии остаётся (tabs-questions Q1).
- Undo закрытой вкладки не возвращается.

## 9. Фундамент (сначала, отдельным PR)

Эти баги есть уже сейчас (доказательства в `docs/investigations/2026-09-23-tabs-options.md` §1):
- `switchDocument()` — единственный путь смены документа. Он делает: flush автосейва → dedup → свежий `EditorState` (закрывает утечку undo) → коммит пауз комментариев → перенос или отмена `ask` по (окно, путь) → закрытие оверлеев → режим по типу файла. Уйти с документа, у которого упало сохранение, нельзя.
- Recent и «недавно закрытые» переезжают в Rust (сейчас localStorage, последний писатель выигрывает).
- Черновики untitled именуются по id вкладки, а не по label окна: так пропадает коллизия `untitled-main.md`. Имя — **`draft-<tab_id>.md`**: сборка до вкладок при уборке удаляет чужие `untitled-*.md`, а `draft-*` не трогает, так что откат не теряет черновики. Старые имена `untitled-*` по-прежнему читаются, уже названный так черновик своё имя сохраняет; уборка чистит оба префикса, только то, на что не ссылается ни живая, ни ожидающая сессия (tabs-questions Q3).

## 10. Реализация (кратко)

- **Вкладки свои, внутри окна** (B-lite из отчёта). Нативные вкладки macOS отпадают: их полоса только сверху, дровер на ней не сделать.
- Живая только активная вкладка: синглтоны `App.svelte` (автосейв, комментарии, watcher, AI) остаются синглтонами. Фоновая вкладка — это `{path, pos, EditorState}`, при возврате сверяются mtime и хеш. Память почти не тратится.
- Rust: реестр `WindowTabs` (label → номер, проект, вкладки, активная), вместе с `OpenFiles` служит для dedup. `AiPending` / `AiQueue` ключуются по (label, path).
- Session v2 хранится в `session-v2.json`, старый `session.json` не трогаем, есть миграция v1→v2. Номер окна и проект сохраняются.
- Cmd+W переводится во фронтенд: сегодня его закрывает Rust по ненадёжному `is_focused()`.

## 11. Тестирование

- **vitest:** фабрика состояний (после переключения история пуста), маршрутизация §5 как чистая функция, выдача номеров, редьюсер дровера (сортировки, выделение протяжкой, порядок), ранжирование фильтра (имя раньше текста, начало имени раньше подстроки).
- **cargo:** стек закрытых, session v2 и миграция, `coup ls` и ошибка мёртвого номера.
- **Playwright на `npm run dev`:** дровер с моком `invoke`.
- **`dev:app` + MCP-мост:** окна, фокус, перетаскивание между окнами по возможности. Синтетические события отправлять с `e.code`.
- **Доступность:** дровер `role=tablist`/`tab`, стрелки, `aria-selected`. Непросмотренное обозначается не только переливом, но и текстовой меткой.

## 12. Отклонено

| Идея | Почему |
|---|---|
| AI-стол, одно окно на всех агентов | Не couplet-way: изолирует ИИ вместо интеграции (решение владельца 2026-09-24) |
| Вкладка-полоса на каждого агента | ~20 компенсирующих механизмов, 8 вечных полос |
| Верхняя полоса вкладок и нативные вкладки macOS | Забивает окно; дровер решает ту же задачу без хрома |
| Автозакрытие по LRU или по таймеру | Выселяет нужное; вместо этого `transient` и сортировки |
| Hex-id с префиксами | Номера 1–99 проще; точное совпадение |
| Толщина хлястика по числу вкладок | Лишний сигнал, перелив сообщает главное |
| HTML5 drag-and-drop между окнами | Конфликт с нативным сбросом файлов, сброс без данных и координат (§6) |
| Хоткеи с Control для открытия дровера | Непривычно владельцу (2026-09-24). Для переключения вкладок ⌃Tab оставлен — это стандарт |
| ⇧Tab для следующей вкладки | Занят: убрать отступ в списке, предыдущая колонка в таблице |
| ⌘D для дровера | Занята мультикурсором CodeMirror; выбрана ⌘J (2026-09-24) |
