# Вкладки в couplet — черновик v2 (на прожарку)

Контекст: couplet (бывший md-mini) — минималистичный macOS markdown-редактор, Tauri 2 + Svelte 5 + CM6. Сейчас строго «один документ = одно окно» (принцип исходной спеки: «No tabs»). ИИ-агенты (Claude Code) ведут его через MCP/CLI: `show <file>` — открыть/сфокусировать, `edit` — втолкнуть содержимое в буфер, `ask` — вопрос с кнопками, комментарии-сайдкары `.mdmini_comments_<doc>.md`. У владельца обычно несколько параллельных агентов в разных репо/worktree, каждый показывает ему отчёты/планы через `show`.

## Страхи владельца
- F1 взрыв количества (Chrome/Sublime)
- F2 страшно закрыть
- F3 невозможно держать в порядке
- F4 вкладки/окна забивают экран
- F5 ИИ должен хорошо с ними работать (агент открывает сам, может спамить)
- F6 компоновка — какие вкладки в каком окне

## Факты из кода (проверены)
- Все реестры Rust (`OpenFiles` path→label, `PendingFiles`, `FileWatchers`, `AiQueue`, `SessionState`) ключуются по label окна; один watcher на окно.
- ИИ адресует документ по абсолютному пути; не открыт → `open_file_window` → новое окно. Каждый `show` нового файла сейчас = новое окно.
- CLI не передаёт cwd в show/edit; у каждой сессии Claude Code свой процесс `md-mini mcp` (identity агента доступна).
- Закрытие окна не спрашивает — автосейв 300мс. Untitled не автосейвится; по коду Cmd+W на untitled-окне теряет текст (session entry удаляется, сайдкар потом GC) — не проверено в рантайме.
- Cmd+O и Recent Files заменяют документ в текущем окне (in-place). Recent Files панель (10 штук) уже есть.
- Cmd+Shift+T занят «Reopen Session». Window-меню нет. Нативный tabbing явно не включён; tauri-runtime-wry выключает automatic tabbing, если tabbingIdentifier не задан.
- App.svelte держит ~15 per-window синглтонов (fileState, autosave/recovery таймеры, comment drafts/pending/countdowns, ai hints, external-change handler, проверка «window owns this file»).

## Корень страхов (по исследованиям)
- Вкладку держат как напоминание/todo и из страха «чёрной дыры» (CHI 2021, CHI 2010). Если закрытое уходит в видимое место и возвращается одной клавишей — страх снимается.
- Разрастание = открывать дёшево, закрывать вручную. Главный генератор открытий в couplet — ИИ (прецедент: Claude Code в VS Code открывает diff-вкладку на каждый Edit → «fills the editor with stale diff tabs»).

## Центральная идея: вкладка — это МЕСТО, а не файл
Два вида вкладок:
1. **Мои вкладки** — возникают только от моего намерения (Cmd+O, Cmd+T, Finder, CLI от меня, drag-drop, правка/pin агентской). Живут, пока я не закрою.
2. **Полоса агента (lane)** — одна вкладка на агента (MCP-сессию; для голого CLI — на git-корень пути). Все `show`/`edit` этого агента идут в неё, заменяя документ; предыдущие — в истории вкладки (⌘[ / ⌘] как в браузере). Агент может показать 20 файлов — это одна вкладка с историей 20.
   - Документ из полосы становится «моим» (отдельной вкладкой), если я его правлю руками / pin / «Keep» — как VS Code preview.
   - Непрочитанное (показано, но я не фокусировал) — точка на вкладке.
   - Полоса умершего агента (MCP-процесс вышел) закрывается сама, когда она чистая и прочитана (или остаётся до конца дня?) — вопрос.

Итог по F1: вкладок ≈ (число агентов, которые сейчас со мной говорят) + (мои намеренные). Растёт по числу разговоров, а не по числу файлов.

## Страховочная сетка (закрытие всегда безопасно — F2)
- Сохранённый файл закрывается без потерь (он на диске). Untitled — никогда не теряется: при закрытии уходит в drafts (app data) и в «Недавно закрытые».
- Cmd+Shift+T = «вернуть последнюю закрытую» (браузерная семантика); если в этом запуске ничего не закрывали — восстанавливает прошлую сессию (сливаем с текущим Reopen Session). Recent Files панель становится «архивом»: недавно закрытые сверху.
- Команды «Закрыть прочитанные агентские», «Закрыть все кроме этой» — безопасны, потому что всё обратимо.
- Мягкий лимит/протухание (LRU, TextMate/JetBrains/Arc) — НЕ в первой версии; lanes и так ограничивают рост. Вернуться, если мои вкладки всё же разрастутся.

## Компоновка (F6, F4)
- Новые вкладки — во фронтальное окно; полоса агента живёт там, где уже живёт (или во фронтальном). Автоматических окон-на-проект НЕТ (иначе вместо tab sprawl получаем window sprawl).
- Вытащить вкладку в своё окно — можно (drag / Move Tab to New Window).
- Полоса вкладок скрыта при 1 вкладке. Порядок предсказуемый: мои слева в порядке открытия (новая — справа от текущей), полосы агентов справа.

## Архитектура: три варианта реализации
**A. Нативные вкладки macOS** (вкладка = NSWindow+WKWebView). Сохраняет весь фундамент «одно окно = один документ» (session, recovery, watchers, AI-роутинг, комменты не трогаем). Полоса агента = окно, в котором документ заменяется (in-place замена уже есть — Cmd+O). История — стек путей в фронтенде окна. Нужно: tabbingIdentifier + objc `setTabbingMode:preferred` (или addTabbedWindow), Window-меню (set_as_windows_menu_for_nsapp), решить маркер непрочитанного (title-префикс или NSWindowTab.accessoryView). Прецеденты: iA Writer, MarkEdit.
 Цена: память ~40–110MB на вкладку (WebContent-процесс на окно), вид полосы системный (не кастомизируется), баг tauri #6548 (fullscreen), меньше контроля над порядком/маркерами.
**B. Вкладки внутри приложения** (один EditorView, Map<docId, EditorState>, setState). Своя полоса (можно в titlebar), полный контроль вида и маркеров, память ≈ текст. Цена: переписать все per-window реестры на per-document (OpenFiles path→(label,docId), FileWatchers per doc, AiQueue, comment_pause document_of_window, SessionState v2), ~15 синглтонов App.svelte → per-doc, ViewPlugin'ы пересоздаются на setState (mermaid SVG cache, cell-edit overlay, live-render toolbar), compartments в каждом state, вынос вкладки в окно — сложно.
**C. Без полосы вкладок** (бэкенд B или A + свитчер ⌘P/⌃Tab MRU, на экране ничего). Максимум минимализма, но скрытое накопление и хуже с «напоминанием».
**0. Шаг ноль без вкладок**: сделать «полосу агента» в текущей оконной модели (одно окно на агента с историей) + страховочную сетку. Уже снимает главный генератор мусора (ИИ-окна). Затем A включает группировку окон во вкладки.

## Рекомендация (черновая)
0 → A: сначала полосы агентов + страховочная сетка в текущей модели (без вкладок вообще), потом нативный tabbing как слой представления. B — только если нативная полоса/память окажутся неприемлемы; политика (виды вкладок, lanes, сетка) переносится.
