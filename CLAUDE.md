# couplet (formerly md-mini)

Minimalist live-preview markdown editor for macOS. Tauri 2 + Svelte 5 + CodeMirror 6.

| Command | Description |
|---------|-------------|

| `npm run dev` | **Default for visual checks.** Frontend only (Vite at http://localhost:1420). No Tauri shell — open the URL in any browser. |

Own bundle ID, own single-instance socket, and own data directory (`~/Library/Application Support/couplet-dev/`) — does NOT conflict with an installed production app. Use when you need Tauri IPC (file I/O, menu, native dialogs). |

| `npm run build:dev` | **Renamed dev .dmg** (`couplet-dev`). Safe to install alongside production. |

| `npm run build:universal` | **Production universal .dmg** (Apple Silicon + Intel). Same owner-triggered rule as `tauri build`. |
| `npm run tauri build` | **Production build (creates .dmg).** Replaces the user's installed couplet if installed. **Explicit, owner-triggered only — do NOT run as part of routine dev/QA.** |
| `npm run tauri dev` | Tauri dev with **production identifier**. Conflicts with running production couplet (shares single-instance socket, app data, recovery files), and refuses to start at all while an installed md-mini's data is still unmigrated (`migration.rs`, B3). **Use `npm run dev` or `npm run dev:app` instead.** |
| `npm run build` | Frontend build only (no Tauri bundle) |
| `npm run dev:site` | Dev server for the **couplet.pro landing** (Vite at http://localhost:1421). Never run alongside `npm run dev` — see the two-servers gotcha below. |
| `npm run build:site` | Build the landing from `site/` into `docs/`. Run `rm -rf docs/assets` first; read `site/CLAUDE.md` before touching the landing. |

### Build / Test Policy While User Is Working

- **Default for visual verification:** `npm run dev` (browser). Most couplet features are frontend; the editor, CodeMirror, decorations, mermaid all run in the browser context.
- **When Tauri features are needed:** `npm run dev:app`. Different identifier → different bundle ID → independent of the installed production app.
- **NEVER run `npm run tauri dev` or `npm run tauri build` as part of routine development or QA.** Both share state with the installed production app and can disrupt the user's active session. Production build is an **explicit owner-triggered action**, never an automated step.

## Code Style

### TypeScript / Svelte
- Svelte 5 runes API only — `$state`, `$derived`, `$effect`, `$props`. No Svelte 4 syntax.
- Strict TypeScript. No `any`.
- CM6 extensions: one file per concern, assembled in `setup.ts`
- Preview decorations: one file per markdown element category
- **RangeSetBuilder ordering:** `Decoration.mark()` BEFORE `Decoration.replace()` at same position (mark has lower startSide)
- Stores: Svelte 5 runes-based (not Svelte stores). Document content lives in CodeMirror state, NOT in Svelte stores.
- Imports: use `@tauri-apps/api` for Tauri JS, `@codemirror/*` for CM6

### Rust
- Tauri 2 command pattern: `#[tauri::command]` async functions in `commands.rs`
- Atomic file writes: write to `.tmp`, then `fs::rename`
- Error handling: return `Result<T, String>` from commands
- Use `tauri::Manager` trait for `app.get_webview_window()`, `app.webview_windows()`
- Note: Tauri 2 has NO `app.get_focused_window()` — iterate `webview_windows()` instead

## MCP dev bridge (agent-driving)

Lets an agent verify features in the actually-rendered app instead of jsdom. Two halves, **both pinned to the same minor**: the MCP server `@hypothesi/tauri-mcp-server@0.12.0` (client side, `.mcp.json`) and the in-process crate `tauri-plugin-mcp-bridge` 0.12 (`src-tauri/Cargo.toml`). The plugin listens on a local WebSocket (base port 9223, scans up to 100), which is why this works on macOS where `tauri-driver` does not.

### How to run

```sh
npm run dev:app -- --features mcp-bridge
```

Under the dev config, never the production one: a debug build on the production identity (`couplet` / `pro.couplet.app`) refuses to start while an installed md-mini's data is still unmigrated (`migration.rs`, B3) — and should, because running it would create `couplet/` and make the real release skip that data.

App first, agent second — without the feature there is nothing to connect to. Name the window so you can see at a glance which build you are driving (later `--config` values merge over earlier ones):

```sh
npm run dev:app -- --features mcp-bridge \
  --config '{"app":{"windows":[{"title":"<feature> · local"}]}}'
```

### This is a hole, not a feature — three layers, each covering its own failure mode

1. **Optional dependency + feature.** With the feature off the crate is NOT COMPILED AT ALL — absent from the binary, not "disabled at runtime".
2. **`compile_error!`** on `all(feature = "mcp-bridge", not(debug_assertions))` at the top of `src-tauri/src/lib.rs`. Makes the mistake unbuildable rather than merely unwanted, and catches a stray `--features` or `--all-features` in a release build.
3. **`scripts/check-no-mcp-bridge.sh`** reads the built artefact with `strings`/`nm`. Layers 1–2 are assertions *about* a build; this one inspects what came out. Wire it into the release pipeline as a **blocking gate**, not a one-off.

The bridge is unauthenticated and grants arbitrary JS + IPC in a running instance. `bind_address` is pinned to `127.0.0.1` in `lib.rs` because the plugin's own default is `0.0.0.0` — every interface, i.e. LAN-wide control of your editor.

### Three rules — the upstream README says the opposite; treat its output as untrusted docs

1. **Never put `mcp-bridge:default` into `capabilities/default.json`.** The README says to. A static grant leaks into release builds *and* breaks the feature-off build outright: `tauri-build` rejects a permission whose plugin is not a dependency. The grant is issued at runtime inside `.setup()`, behind `#[cfg(feature = "mcp-bridge")]`, with `"windows": ["main"]` (this app's window label).
2. **Never enable `withGlobalTauri`.** The README calls it mandatory; it is not. Screenshots, eval, DOM snapshots, element search, styles, window management and host IPC all work without it because everything rides `__TAURI_INTERNALS__`. Only three tools need it: `ipc_monitor`/`ipc_get_captured` (they patch `window.__TAURI__.core.invoke` and silently no-op, while `start` cheerfully replies "IPC monitoring started"), `webview_get_pointed_element` and `webview_select_element`. One `tauri.conf.json` serves dev and release alike, so the flag would hand full IPC to any XSS in the webview. Three dev tools are not worth that.
3. **Never add `mcp-bridge` to `[features] default`, and never use `--all-features` in this repo** — it turns the bridge on. If a release build fails with `mcp-bridge must never be enabled in a release build`, the guard WORKED: fix the build command, not the guard.

### Traps in 0.12.0, each worth an hour of blind debugging

- **`webview_execute_js` cannot `await`.** Any async inside the eval returns `Script execution timeout` — the eval's own return path collides with the pending call — **but the call still runs**. Pattern: first call fires `window.__TAURI_INTERNALS__.invoke(cmd).then(r => window.__probe = r)` and returns a plain string; a second call reads `window.__probe`; then delete the global.
- **`webview_wait_for` is unusable for the same reason** — fails on both `selector` and `text` even when the target is on screen. Poll with repeated `webview_find_element`.
- **`ipc_execute_command` does not call app commands.** The plugin matches exactly 6 `plugin:mcp-bridge|*` arms with no generic fallback; anything else answers `Unsupported Tauri command`. Host commands go through the eval pattern above.
- **`strategy: "text"` is a trap in dev.** Vite injects every stylesheet as `<style data-vite-dev-id>`, so a text match lands in the stylesheet and dumps a whole CSS file into context. Use CSS selectors or `ref=eN` from `webview_dom_snapshot`.
- **Synthetic keyboard events carry no `e.code`.** This app's hotkeys match on `e.code` (the right way — layout independent), so `webview_keyboard` will NEVER fire them, silently, looking exactly like a broken feature. Dispatch yourself: `document.body.dispatchEvent(new KeyboardEvent('keydown', {key:'a', code:'KeyA', bubbles:true, cancelable:true}))` — on `document.body`, not `window`/`document`, because handlers often bail on `isEditableTarget(e.target)` and a non-Element target fails that check. Limit of the evidence: synthetic events bypass the OS/webview path, so they test the handler, not that a real keypress reaches it.
- **Make sure you are testing the build you think you are.** `ipc_get_backend_state` returns `cwd`. This repo also points cargo at a **shared target directory** (`~/.cargo/shared-target`), so `target/release/` can hold a bundle from an entirely different checkout — `check-no-mcp-bridge.sh` refuses to bless an artefact older than the sources for exactly this reason.
- **Don't name a branch or worktree `*mcp-bridge*`.** Tauri compiles `CARGO_MANIFEST_DIR` into the binary, so the build path itself matches a naive `grep mcp-bridge` and fails the gate on a perfectly clean binary. The gate's strong checks (crate name, `plugin:mcp-bridge|` ACL ids, `nm` symbols) are what actually detect a linked plugin.

### Second instance side by side

The vite config pins `strictPort: true` on its port, and the dev identity owns one single-instance socket, so a second dev app needs four things, not one:

```sh
CARGO_TARGET_DIR=~/.cargo/<slug>-target npx vite --port 1421 --strictPort &
CARGO_TARGET_DIR=~/.cargo/<slug>-target npm run dev:app -- --features mcp-bridge \
  --config '{"productName":"couplet-<slug>","identifier":"pro.couplet.<slug>",
             "build":{"beforeDevCommand":"","devUrl":"http://localhost:1421"},
             "app":{"windows":[{"title":"<feature> · local"}]}}'
```

`beforeDevCommand` is silenced so tauri does not raise a second vite over yours. `CARGO_TARGET_DIR` is not optional: with a shared target another build overwrites your binary, and someone else's `pkill` by binary path kills your window.

## Gotchas

- **Never pass a `bool` literal to an Objective-C API.** `objc`'s `BOOL` is `bool` on aarch64 but `c_schar` (`i8`) on every other target, so `ns_app.activateIgnoringOtherApps_(true)` compiles on Apple Silicon and fails the x86_64 build with `expected i8, found bool`. Use `cocoa::base::YES`/`NO`, which are defined per arch. This kept Intel builds broken until 2026-08-23 and is invisible unless you actually cross-compile — `npm run check:x86` is the guard.
- **Svelte 5 runes require `.svelte.ts` extension:** Files using `$state`, `$derived`, `$effect` outside `.svelte` components MUST be named `*.svelte.ts`, not `*.ts`. Plain `.ts` files won't compile runes — the app loads a white screen with no errors. `npm run check` does NOT catch this.
- **Kill port 1420 before `npm run tauri dev`:** Previous dev sessions leave Vite running. Use `lsof -ti:1420 | xargs kill -9` to free the port.
- **GFM required:** `@lezer/markdown` needs explicit `extensions: [Strikethrough, Table]` in the markdown() call — without this, `~~strikethrough~~` and tables don't produce AST nodes
- **Decoration ordering:** CM6 RangeSetBuilder crashes if decorations aren't in `(from, startSide)` order. `Decoration.mark` goes before `Decoration.replace` at the same position.
- **No cross-line Decoration.replace:** Replacing text that crosses `\n` boundaries causes rendering glitches. Use line decorations (e.g., `Decoration.line({ class: 'hidden' })`) instead.
- **Slash commands vs closeBrackets:** Don't use `autocompletion({ override: [...] })` — it replaces ALL completion sources. Use `EditorState.languageData` to add completion sources alongside existing ones.
- **Svelte 5 exports:** `export function` from `<script>` doesn't work in runes mode. Use `bind:this` + public `$state` properties.
- **Svelte 5 `$bindable` for handles:** To expose EditorView from Editor.svelte, use a `$bindable()` handle prop with an interface, not `export let` or `export function`.
- **Tauri 2 MenuId:** Use `event.id().as_ref()` not `event.id().0` to get menu item ID string.
- **Single instance:** `tauri-plugin-single-instance` callback receives `&AppHandle`, not owned. `args[0]` is the binary path — skip it.
- **Font paths:** Vite resolves `url()` in CSS relative to the CSS file. Put fonts in `src/assets/fonts/` and reference as `/src/assets/fonts/Foo.woff2`.
- **macOS CLI launcher:** GUI apps cannot be backgrounded with `&` / `disown` / `nohup` — lose window server access. Use `open /path/to/app.app` for launch, single-instance socket IPC for file args. See `docs/cli-launcher.md`.
- **Single-instance stale socket:** `kill -9` leaves `/tmp/pro_couplet_app_si.sock` — new instances think app is running and exit silently. Delete socket to fix: `rm -f /tmp/pro_couplet_app_si.sock`
- **Tauri 2 `onCloseRequested`:** Registering a JS listener automatically calls `api.prevent_close()`. The handler MUST call `window.destroy()` or the window will never close. Prefer handling close in Rust `on_window_event` instead.
- **Lezer GFM tables exclude whitespace-only rows:** New/empty table rows must contain visible content (e.g., `-`) or Lezer won't include them in the Table syntax node.
- **Table delimiter detection:** Use position-based (2nd line of table), NOT regex. Regex `\|[\s|:-]+\|` matches data rows containing dashes.
- **CM6 widget `eq()` must compare structural context:** If a widget holds document positions (like TableContext), `eq()` must compare them. Otherwise CM6 reuses stale widgets after edits.
- **CM6 fold API:** Use `foldable(state, from, to)` to query fold ranges. Do NOT access `foldService.value` directly.
- **CM6 gutter elements get clipped:** `overflow: hidden` on `.cm-content` clips absolute-positioned elements. Use `padding-left` + `::before` within the line instead of negative `left` offsets.
- **`/usr/local/bin/couplet` and `/usr/local/bin/mdmini` must be COPIES** of `scripts/couplet` / `scripts/mdmini`, not a symlink to the binary. `cp` over a symlink follows the symlink and corrupts the target.
- **CM6 CSS specificity:** CM6 uses generated selectors like `.ͼ1 .cm-line` (2 classes). To override, use `.cm-line.cm-md-table-line` (also 2 classes), not just `.cm-md-table-line` (1 class).
- **CM6 `cm-widgetBuffer` images:** CM6 adds hidden `<img>` elements around widget decorations. In inline formatting context they add ~14px height per line. Use `display: flex` on parent line to eliminate this.
- **CSS `contain: inline-size` for wide widgets:** Prevents wide tables/widgets from expanding `.cm-content` (which breaks `lineWrapping`). Apply on `.cm-line`, move visual styles (background, border) to widget wrapper so they match content width, not viewport width.
- **CM6 widget-hosting line must stay visible:** When replacing a fenced block with a widget (`Decoration.replace`), the `.cm-line` that hosts the widget must NOT have `height: 0` or `overflow: hidden`. The widget is a child of `.cm-line` — hiding it clips the widget. Only hide subsequent lines.
- **Mermaid render is async:** `mermaid.render()` returns a Promise but CM6 `WidgetType.toDOM()` is sync. Use placeholder widget + `StateEffect` to trigger decoration rebuild when SVG is ready. See `preview/mermaid.ts`.
- **Natural-size SVG needs a contained host line:** giving a widget SVG its intrinsic width (required for exact zoom math) stretches `.cm-content` and breaks line wrapping *document-wide*, even with `overflow: hidden` on an inner wrapper. Put `contain: inline-size` on the hosting `.cm-line` via a line decoration. Symptom: `.cm-scroller` gains horizontal overflow.
- **Block widgets must have ZERO vertical CSS margins on their root element.** CM6's height map measures widget height without margins, so every line below the widget sits lower in the DOM than the map thinks. `posAtCoords`'s vertical-scan mode then mis-resolves ArrowUp/Down across the widget — the caret skips all lines between it and the widget's host line. Put spacing as `padding` on an outer wrapper inside the widget DOM instead (padding is part of offsetHeight).
- **Never dispatch a CM6 transaction per animation frame:** interactive gestures (pan/zoom) must write to the DOM directly and commit to a `StateField` on a trailing debounce. A dispatch per `wheel` event triggers a full decoration rebuild each frame.
- **Widget `eq()` should exclude the document position** when the widget is expensive to build: including it rebuilds the DOM on every keystroke elsewhere in the file. Resolve the live position at commit time with `view.posAtDOM(dom)`, snapped to `doc.lineAt(...).from`.

On macOS terminate the `Destroyed` storm turns out not to happen, but the close-last-window path does emit it.

- **On-disk state must go through `paths::app_data_dir()`,** never `dirs::data_dir().join("couplet")`. The directory is named after the product name, so a dev build gets `couplet-dev/` and cannot overwrite an installed release app's `recovery/` (which holds the user's unsaved work) or `session-v2.json`. `paths::init` runs as the first statement in `setup`, before anything reads or writes.

So any state that reads app data at construction — `RecentFiles::load()` — is managed inside `setup` after `paths::init`, never on the builder, and such a type must never get a disk-reading `Default`: one stray `Default::default()` and a dev build loads the installed app's list.
- **Single-instance callbacks can run before `setup` has managed state.** The plugin's callback fires on its own task and may open a window while `setup` is still running. Use `app.try_state::<T>()` there and in anything it calls: `state()` panics, and a panic there ends the CLI listener for the rest of the run.
- **`npm run test` overcounts:** vitest picks up stale copies under `.claude/worktrees/`. Use `npx vitest run --dir src` for a true count (1838 after tabs plan 05).
- **Backspace needs `Prec.highest`, not `Prec.high`.** Backspace is in the view's `PendingKeys` table paired with `inputType: "deleteContentBackward"`, so on a contenteditable the native edit is allowed to land and is reconciled afterwards rather than being resolved from `keydown` alone. A binding at `Prec.high` is **never entered at all**, and the failure is not a clean fall-through — the DOM-derived change is applied instead. With the list bullet rendered as a widget, that reconciliation rewrote `- b` as `  b`: a silent outdent, text still inside the item. Measured in a browser; unit tests calling the command directly all passed throughout. Escape at `Prec.high` is fine — this is specific to keys that carry an `inputType`.
- **A completion source must be a STABLE reference.** CM6 calls the arrow passed to `EditorState.languageData.of()` on *every* `languageDataAt` lookup — not once at setup — and compares the returned providers **by identity** to decide whether the active source set changed. So `languageData.of(() => [{ autocomplete: mySource(deps) }])` hands back a new closure and a new object every lookup, which CM6 reads as "the sources changed" on every query, forever: it drops the results and re-runs. Symptom: the popup never opens **for any command**, `completionStatus` is permanently `pending`, and the idle editor churns ~10 transactions/second from `scheduleAccept → accept → dispatch` inside `completionPlugin`. Build the source and the record once, outside the arrow. This survived `npm run check`, 1277 vitest tests and both cargo suites green — unit tests call the source directly and see correct options, because only the identity *between* calls is broken. Caught only by running the real browser against `origin/main` side by side. `slash-commands.test.ts` and `slash-theme.test.ts` now assert two consecutive `languageDataAt('autocomplete', pos)` return `toBe`-identical functions.
- **A no-op `changes` does not close the completion popup.** CM6 drops a source's cached result only when a transaction carries `docChanged` or an explicit `selection`. An `apply()` that deletes the typed filter with `{from, to, insert: ''}` is a pure no-op when nothing was typed (`from === to`) — the common path of "open the list, arrow to a choice, hit Enter" — so the popup keeps rendering the stale option set even though the picker's own StateField already closed underneath it. The commit *did* run; only the visuals lie. Add an explicit `selection` to the same position to force the invalidation. The mirror image is useful too: re-dispatching the picker's open effect plus `startCompletion()` makes the list requery itself in place, which is how `/tone` applies a choice and stays open so the user can see it and change their mind.
- **A completion popup that previews something must not preview whatever CM6 auto-selected.** CM6 sorts by score and selects index 0, so `/theme` repainted the whole window to an unrelated theme the instant it opened. Two parts: `boost` per option to impose a real order (with an empty filter, match scores tie and `boost` decides), and `setSelectedCompletion` to move the selection onto the current value once `completionStatus` first reads `'active'`. The second part needs a "selection placed yet?" flag that suppresses the preview **entirely** until the correction lands — otherwise one frame of the auto-selected option still shows, which is the flash you were removing.
- **Reveal policy is per element, not per mode** (`preview/flavour.ts`). Decorators call `shouldReveal(view, kind, from, to, blockLevel?)`, never `cursorInRange` directly; `cursorInRange` stays pure and is called from inside it. `live-preview` is `{default: 'on-cursor'}` — today's behaviour comes out of the same code path instead of being preserved by discipline. Adding a flavour means adding a `Flavour` literal, not a branch.
- **`- [x] done` is `Task > TaskMarker`, never `Link`.** `markdownLanguage` already bundles GFM, so task lists parse natively and there is no checkbox/link collision to guard against. The real lookalike is `- [x](url) text`: `TaskList.parseBlock` requires whitespace after the bracket, so that parses as a plain inline `Link`, while `lists.ts`'s text-only regex still draws a checkbox over it. Also note that regex is case-**sensitive** — `[X]` renders no checkbox at all.
- **Hiding markers permanently does not remove reflow, it moves it.** A marker is only hidden once Lezer has a completed node, so while typing `**bol` you see raw text and the four characters vanish at once when the closing `*` lands. The jump is sharper than the one it replaces, just at a different moment.
- **Two declaration sites for hotkeys, and only one is TypeScript.** Inline-format keys live in `INLINE_FORMAT_BINDINGS` (`keybindings.ts`); `ai_comment`'s `CmdOrCtrl+Shift+M` lives in the native menu (`src-tauri/src/menu.rs`). A UI caption built from the first will silently render key-less for an action whose key is in the second. `native-menu-accelerators.ts` mirrors the Rust and its test parses `menu.rs` for set equality — a mirror without that test drifts back within a month, and nothing in a running app compares a tooltip to a menu.
- **A freshly created `EditorState` may have no syntax tree yet.** `syntaxTree(state)` returns whatever the initial budgeted parse produced, which for a state built on the spot can be `Tree.empty`. Tree-aware commands then find nothing and take their "add" path every time — bold switches on and never off. Use `ensureSyntaxTree(state, len, timeout)` when the state was not built by the view.
- **Never assign `textarea.value` to apply an edit you want undoable.** It wipes the element's native undo stack, taking the user's own typing with it. Narrow the rewrite to the changed span and put it through `execCommand('insertText')` — deprecated, implemented in both engines this app runs in, and the only way onto that stack. See `cell-edit-session.ts`.
- **Atomic ranges protect the caret, not the edit.** `EditorView.atomicRanges` and `caretNormalizeFilter` both reason about *positions*; neither looks at `tr.changes`. So the caret is always legal and an edit from that legal position still tears hidden markup — and `skipAtomic` widening a Backspace over a whole `**` is the *correct* caret behaviour that causes it. Editing needs two more layers: `live-render/markup-delete.ts` for intent (at the key, `Prec.highest`) and `live-render/markup-repair.ts` for the invariant (a `transactionFilter`). Neither substitutes for the other.
- **The repair filter must exempt undo/redo.** History replays the repaired change's own inverse, which is well-formed by construction — but that inverse deletes marker text, which any "a pair was torn" rule reads as damage and repairs straight back, so undo stops undoing. Measured: `**жир****ным**`.
- **CM6 applies `transactionFilter`s in reverse facet order** — the last registered runs first. That is how `markupRepairFilter` gets to run before `caretNormalizeFilter` despite being added after it.
- **Two offsets at one pixel are not reached by the same gestures.** `skipAtomicRanges` only moves a caret *strictly* inside a marker, so arrow motion and the mapped position after an insertion stop at a span's inner edge, while a click resolves the tie outward. The offset already encodes intent; redirecting insertion at the outer offset back inside is what produced "click after a bold word, type, get bold".
- **Search in `live-render` runs against the source, not the screen.** `boldtext` inside `**bold**text` is unfindable, and searching `**` yields hits that are not rendered. A visual-text search index is the only real fix; until then it is a documented limitation of the mode.
- **Every write into a directory the *user* owns goes through `atomic_write::save`** — the document (`commands.rs`) and the comment sidecar (`comments.rs`) both, and any third one that appears. `fs::write` + `rename` looks equivalent and is not: it loses mode, owner, ACL and xattrs, creates the temp at `0644` whatever the destination is, never `fsync`s, and turns an `everyone deny delete` ACL into a save that fails forever. #18 fixed this for the document and #54 found the same defects still live in the sidecar, which is why there is one function and not two. `recovery.rs`, `session.rs` and `recent.rs` are the deliberate exceptions: they write inside the app's own data dir, where there is no user metadata to keep.
- **The only per-caller knob is `NewFileMode`.** `Umask` reproduces `fs::write` for a file the user named themselves; `Like(model)` gives a *derived* file the model's mode, because a comment sidecar quotes the document and must not be more readable than it. A `Like` whose model is gone stays `0600` rather than widening — an unknown-confidentiality file is one to keep closed.
- **A temp file beside a sidecar must not itself look like a sidecar.** `comments::is_sidecar` matches the `.mdmini_comments_` prefix, and the old temp name (`with_extension("tmp")`) still carried it — so `collect_open` could parse a half-written temp as real threads and `mdmini watch` could fire on one. `atomic_write::temp_path_for` prepends a dot unconditionally, producing `..mdmini_comments_…`; the double dot is load-bearing, not untidy.
- **Window zoom is webview page zoom, not a `font-size` cascade.** Cmd +/− used to set `font-size` on `<main>`, and that scaled exactly one thing: the slash-menu tooltip. Inside the editor `.md-editor-host .cm-scroller { font-size: 16px }` (`styles/editor-metrics.css`) overrode it, and toasts, badges and the recent-files panel live outside `<main>` altogether. `lib/window-zoom.ts` calls `WebviewWindow.setZoom` instead — wry routes it to `WKWebView.setPageZoom` (macOS 11+), i.e. a real reflowing zoom, not `magnification`: the text rewraps to the window and no horizontal scrollbar appears. CM6 keeps seeing unchanged CSS pixels, so its geometry needs no patching — `posAtCoords` was measured exact at 140%. Two things to know: it needs `core:webview:allow-set-webview-zoom` in `capabilities/default.json`, and without it the rejected IPC disappears into `.catch(() => {})` and the feature is silently dead; and page zoom lives in the webview rather than in the setting, so **every window applies the stored level when it is created**. Do not swap this for the builder's `zoom_hotkeys_enabled` — its own counter is invisible to the store, and Cmd+wheel is already taken by mermaid pan/zoom.
- **A failed sidecar write needs its own toast kind, not `save-error`.** The document's toast says "press ⌘S", which does nothing for a comment, and `performSave` calls `dismissKind('save-error')` on every successful document save — which would wipe a standing comment failure on the next autosave tick. Hence `comment-error`, dismissed by `markCommentSaved`. The sidecar needs a surface at all because it is the one file with no second copy: no dirty flag rescheduling it, no recovery snapshot, and since #23/#36 it holds a reply the human has not sent.
- **A window's `emit` is a broadcast, and a global `listen` also receives targeted emits.** Emitting per window in a loop while the frontend listens globally delivers every event N× to each of N windows — how every menu action ran N×N times until tabs plan 02. Emit once (`app.emit` for everyone, `emit_to(label)` for one window) and listen per window (`getCurrentWebviewWindow().listen`, `lib/tauri/events.ts`). Menu routing lives in `menu_route.rs`; the target is the last `WindowEvent::Focused(true)`, because `is_focused()` is unreliable while the menu bar is in use.
- **`EditorView.setState` runs no update listeners, and compartments belong to the state.** A swapped-in state (a cached tab, a fresh load) keeps whatever preview/language configuration it was built or left with, and nothing derived from `ViewUpdate` (AI-highlight presence → the hint badge, the JSON offer toast) notices the swap. `swapState(state, { blur, scroll })` in `Editor.svelte` recomputes the highlight presence and withdraws the JSON offer; the controller then calls `applyDocumentConfig(path)` (`App.svelte`) after every swap, cached ones included, to reapply language / env / preview config and the code-file class. A language that finishes loading after its state was swapped out is dropped by `latest-only.ts` (`swapState` invalidates it).
- **Tab ownership changes only through calls that check ownership first, under the one `OpenFiles` lock** — the `tab_*` commands in `tab_commands.rs`, and `window.rs`'s handover for tabs a window is born with. `tabs_sync` (the heartbeat) reorders and reports but never claims a path: a reported file tab the registry does not know is ignored, and a tab the report does not mention is kept, because a claim can be in flight while an older report is on its way. Save As goes through `tab_claim` **before** it writes (`lib/tabs/save-as.ts`); `TabClaim::Refused` means nothing was claimed, and it must not write.
- **Lock orders:** `ClosedStack` → `OpenFiles`; `OpenFiles` → `PendingFiles` → `FileWatchers`; `OpenFiles` → `AiQueue`; `OpenFiles` → `AiPending` (`tab_move` re-labels the moved files' requests under the registry lock; nothing takes `AiPending` and then the registry — `ai_respond` and `ai_forward` drop the registry guard first). Never the reverse: don't lock `ClosedStack` or write to disk while holding `OpenFiles` — read what you need, drop the guard, then act (as the `Destroyed` handler does). `AiQueue` is pushed under the registry lock on purpose (`ai_socket::deliver`): whether a window has mounted and whether its command is queued must be one decision, or a command queued after `ai_pull_pending` is never pulled and one emitted before the mount is lost.
- **A tab removed from the registry is tombstoned** (`WindowTabs::closed_ids`, filled by `remove_tab`). A heartbeat sent before `tab_close`/`tab_release` can be processed after it; `sync` would append the unknown untitled id again and `record_heartbeat` would rewrite its sidecar, and the discarded draft would come back next launch. `sync` and `record_heartbeat` both skip tombstoned ids; an explicit `add_tab` clears one.
- **The window init contract.** Every listener that can deliver a tab (`open-file`, `reopen-tab`, `ai-command`, `tabs-arrive`) is registered — awaited — before the frontend calls `get_window_init`: Rust counts the window as mounted from that call on and sends events instead of a payload, and an event with no listener yet is lost. The tabs `get_window_init` returns are already registered: the frontend calls `tab_activate` for the active one (that points the watcher at it) and never `tab_open`. A tab arriving by event is not registered and goes through `tab_open`. The exception is `tabs-arrive` (plan 05): its tabs were moved in the registry by `tab_move` and are shown with `tabs.arrive`, never `tab_open`. Tab sources wait until `tabs.init` is queued (`tabSourcesReady` in `App.svelte`) — the serial queue then runs them after it; one that ran first would work on an empty tab list that init then publishes over.
- **Background file tabs are always clean, and unwatched.** The one watcher per window follows the active tab (`tab_activate` / `tab_claim` / `tab_release`). Leaving a file tab whose save has not landed, or any tab while a save error is pending, is refused (`decideLeave`: an `unsaved-blocked` toast, or the standing `save-error` one) — a cached state has no autosave, recovery snapshot or watcher, so it would be the only copy of that text. Returning to a tab compares the disk with the text it held when it was left (`decideEnter`): equal → the cached state (undo intact), different → a fresh load at the old caret.
- **Line endings are per file, and the buffer is always LF.** `readDocument` normalizes and reports the file's ending; `writeDocument` converts back. The ending travels with the tab, never through a table keyed by path: `disk.read` returns it, `Ready` → `Entry` → `doc.setActive(…, lineEnding)` carry it to `fileState.lineEnding`, `stashActive` puts the current one into the tab's `TabCache`, and a background write (`applyToTabNow`) uses that, so an agent's edit keeps a CRLF file CRLF. A path-keyed map was tried and broke on the first alias: a file opened as `/tmp/x.md` is registered as `/private/tmp/x.md`, the lookup under the registry's spelling found nothing, and the first autosave wrote LF. `createDocumentState` normalizes too, as the backstop: a caret placed from a CRLF string's length is past the end of CM6's document and throws `RangeError` — how a Windows file used to open as an empty Untitled window.
- **A file that changed on disk and will not read pauses autosave** (`diskUnreadable`, `canAutoSave`) with a standing `reload-error` toast and a retry timer; ⌘S is the human saying "my version wins". It also holds the tab where it is: `holdsBack` includes it, so a dirty tab cannot be left while its disk is unreadable, and `reportSwitchBlockedByUnsaved` stays quiet because the reload-error toast already says why. Showing any other tab ends the state (`setActiveDocument` → `endDiskUnreadable`).
- **A state leaving the view takes its `/theme` preview with it.** The preview is cleared only by the picker's own update listener, and neither a background state nor `setState` runs one, so a tab switched away mid-pick left the next tab in a theme nobody committed. `stripLeavingState` (`tab-cache.ts`) closes both pickers first — in their own transaction, because the popup closing under an open picker reads as an abort whose microtask deletes the typed filter from the view's *next* state, another tab's text — then the completion, then calls `previewFamily(null)`. `swapState` backs it up for any swap that skipped the strip.
- **An agent's disk reads are `quiet`** (`DiskOptions`): `textForAgentNow`, `applyToTabNow`, `openBackgroundNow` and an agent's `openPathNow` fail into the agent's answer, without the `open-error` toast a human's open raises.
- **`runExclusive` holds the tab queue: inside it never call a queued method.** AI commands run in the controller's serial queue so a command arriving mid-switch waits instead of failing. A queued method (`openPath`, `activate`, …) awaited from inside `runExclusive` waits for that very slot and never runs. The `*Now` methods (`activateNow`, `openPathNow`, `openBackgroundNow`, `placeCaretNow`, `applyToTabNow`, `textForAgentNow`, `closeTabNow`, `markUnviewedNow`, `markTransientNow`) and synchronous non-queued helpers (`findByPath`) are fine — and the agent-only ones refuse to run *outside* the slot (`requireExclusive`: console error, no change), since a stamp from outside could land between a switch's steps. A command that waited behind a switch may already have been answered (its tab was closed, or it timed out) — `agent-commands.ts` asks `ai_is_pending` first and drops it if not; when that IPC itself fails it does nothing and answers `could not confirm the request is still pending`, never guessing either way.
- **Session v2 lives in `session-v2.json`; `session.json` is never written.** At startup both are read and the one saved last wins (v2 on a tie); a file that does not parse loses to one that does, so a corrupt v2 falls back to v1 (migrated: one tab per window). Newest-wins rather than v2-first because an older build run after this one (a rollback, another branch's dev build) writes only `session.json`. Untitled sidecars are named by tab id, `draft-<tab_id>.md` (tabs-questions Q3): a pre-tabs build prunes every `untitled-*.md` its `session.json` does not name, and would delete this build's drafts after a rollback. A sidecar that already has an `untitled-` name — a migrated v1 `untitled-<label>.md`, a pre-Q3 `untitled-<tab_id>.md` — keeps it (`untitled_file_for` returns the recorded name; no rename of the only copy of a draft). The GC (`is_untitled_sidecar`) prunes both prefixes, and only what `referenced_untitled` does not name.
- **The drawer's ⌘L/⌘R/⌘U and ⌘G are webview keys, not menu items.** A capture-phase `keydown` on `window`, installed only while the drawer is open, owns them (and every letter, for type-to-filter) and stops propagation, so CodeMirror never sees them — ⌘U is its `undoSelection`, ⌘G its `findNext`. An open drawer always owns them, however it opened (Q5). `drawer-keys.test.ts` fails if `menu.rs` ever claims one: a native accelerator is resolved before the webview and the drawer would silently stop sorting. ⌘J *is* a menu item (`toggle_drawer`).
- **⌦ / ⌫ close the ⇧-selection** (`drawerKeyAction`'s `close-selected`, then `closeSelected` — the «Закрыть выбранные» button's own path). Matched on `e.code` with any modifiers (⇧ is often still held; ⌘⌫ means nothing in the drawer). ⌫ only while the query is empty — with text it edits the query. Never on auto-repeat (`e.repeat`): a ⌫ held to clear the query would otherwise close the selection, filtered-out tabs included, the moment the query empties. Off during a drag, while the carousel is up (the `canCloseSelection` argument) and while the notch number is edited (its keys never reach `drawerKeyAction`). The button carries the keys as `title` + `aria-keyshortcuts`, like «В окно…».
- **An open drawer has the keyboard, however it opened** (tabs-questions Q5, strictly the spec). A hover-open moves focus into the drawer exactly like ⌘J or a notch click: every printable key without ⌘/⌃ goes to the filter — even one typed mid-sentence while the pointer happened to rest on the notch, a trade-off Max chose — and Esc, arrows, Enter, Backspace, Space and Tab are the drawer's too. There is no "hover leaves the keys with the editor" state any more (the old `DrawerState.typing`, `actionAllowed`, `DWELL_*` are gone). Hover and pinned differ only in closing: a hover drawer closes `HOVER_CLOSE_MS` after the pointer leaves (not while the carousel is up), a letter pins it, ⌘J or a notch click on it pins it instead of closing. Closing puts focus back where it was at the open (CodeMirror keeps its caret); if that was `<body>` or the element is gone, `onrestorefocus` puts it in the editor.
- **"Viewed" = active while the window has focus** (`document.hasFocus()`), not "activated": agents activate tabs too. `unviewed` is set by `markUnviewedNow` (any agent command landing on a tab that is not the active tab of a focused window, plan 04 D9) and cleared by the same focus rule. Stamps ride `tabs_sync` into `session-v2.json` with serde defaults — no session version bump; a quick look's `transient`/`transientSeenAt` ride the same way (Q8). Stamps survive a restart, a session restore (`pending_tab_from_snapshot`) and a move between windows: `tab_move` carries them — with the caret, a quick look's state and the agent inbox — in `MovedTab` → `PendingTab`, and «В новые окна» is such a move now. ⌘⇧T and the other paths that build a window still build a fresh `PendingTab` with `..Default::default()` (`window.rs` `window_init` and `open_file_window`, `closed.rs` reopen, `lib.rs` `assign_file_to_main`), so there the tab arrives as newly opened (`openedAt` = arrival, `viewedAt` 0, `unviewed` false).
- **Moving tabs between windows is one Rust step, `tab_move`, never a release plus an open.** Under the one `OpenFiles` lock it moves the registry entries (`TabRegistry::move_tabs`: all or nothing, the source tombstoned so a late heartbeat cannot bring the tab back, the target's tombstone cleared), re-labels `AiPending` for the moved files (agents keep waiting — on the target — and `ai_respond` from the target is accepted), stops the source's watcher if the file it watches left (`FileWatchers` records its path; the registry's active tab may still name the moved one), and hands the tabs over: `tabs-arrive` to a mounted target — **emitted before the guard drops**, so an agent command routed to the target right after cannot overtake the tabs — or the pending payload of a window built for the move (the same decision `queue_tab` makes). The session snapshot, with the untitled sidecar name, follows after the lock. A `NewWindow` move is pre-checked (`check_move`, short lock) before its window is built, so a refused move shows no window and uses no number, and that window is built on the main thread with `Activation::Background`, so it is never drawn over the human's for a frame. Undo history does not move.
- **A move is neither a close nor a release.** No `tab_release`/`tab_close`, so no `cancel_for_tab`, no ⌘⇧T entry, no recovery deletion — agents never see `tab released`. The source (`controller.moveNow`) swaps to the neighbour *before* the IPC, so the one `await` never sits between the last dirty check and the swap; when the window empties, the stand-in scratch state is **read-only** (text typed there would belong to no tab). The emptied window closes only after whatever already waits in its queue has run, and re-checks it is still empty then: a command queued behind the move is for a tab that left, and must run here to be handed on with `ai_forward` (`AiPending::hand_to`: only a request still waiting and the caller's or already the holder's) instead of being answered `the file is open in another window`.
- **The target of a move never comes forward.** Arrivals go after its active tab; the first is shown unless the active tab may not be left, or an agent's live `ask` is on screen there — then they wait in the background. They are not marked unviewed (a human moved them). The human stays in the source with the `tabs-moved` toast «Перенесено в #N · Перейти» (`reveal_other_window`), the one toast that dismisses itself (6 s, `TABS_MOVED_TOAST_MS`). Likewise an agent's (quiet) open of a file another window holds answers `elsewhere` and never raises that window (plan 05 D5) — the command is forwarded there instead.
- **Renaming `#N` from the notch.** Only with the drawer *already* open. The edit starts on `dblclick` (the platform's double-click, at the system speed), and only if the first click found the drawer open: that click waits `DOUBLE_CLICK_MS` (500, macOS's default speed — a page cannot read the user's) before it does what a notch click does, so it cannot close a pinned drawer under the second. A slower double-click is two clicks; a double-click on a closed notch opens and toggles as before, never edits; the drawer closing drops a waiting click, or Esc within the wait would reopen it. The rest of the notch acts at once. The input is a real `<input>` with `writing-mode: vertical-rl` turned 180°, the notch number's own font and accent — measured in Chrome and Playwright's WebKit 26.5 (`npx playwright install webkit`): caret, select-all, typing, Backspace all work vertically. It is a sibling of the notch button (an `<input>` inside a `<button>` is invalid), inside the drawer root, so `insideDrawer` holds for it; `.wid` stays in the layout, `visibility: hidden`, while it edits. An answer other than `set` that lands after the input lost focus closes it. The drawer's capture-phase `keydown` returns for `.notch-edit` targets, and the input stops propagation of its own keys. Starting an edit pins a hover-opened drawer. `window_set_number` decides under the registry lock (a dead window's entry does not count as holding the number) and writes the session after dropping it; routing, `ls` and the carousel read the registry, so they follow without a push. Other windows learn the change on their next read — nothing is broadcast.
- **A session restore keeps every window's number.** `restore_pending` plans every window first (`plan_restore`: a snapshot whose files are all open elsewhere builds nothing and reserves nothing), collects the planned ones' numbers as `reserved` and first moves `main` off one of them while it is still as it started (no project, no file tab: `make_room_for_restore`), emitting `window-number` to it for its title and notch. A restored window whose own number another live window holds falls back past `reserved`, so it cannot take a later snapshot's number. Without this, #1 A and #2 B came back as #2 and #3 behind main's #1, and `-t 2` hit the old #1. `build_restored_window` numbers the window under the lock *before* `build()` — once built, its frontend can mount and `get_window_init`'s backstop would number it without its preferred or the reserved numbers — and removes the entry if the build fails. `number_window` never renumbers a window that has a number and ignores its own and dead windows' entries.
- **⌃1…⌃9 are webview keys: window `#N` comes forward.** `ctrlDigitHandler` is a capture-phase `keydown` on `window` registered synchronously in App's `onMount`, i.e. before the drawer can add its own (same target and phase → registration order), and it `stopImmediatePropagation`s, so neither the drawer nor CodeMirror sees the key, drawer open or not. Matched on `e.code` (`Digit1`…`Digit9`) with ⌃ alone. A human's key: `window_reveal_number` uses the plain `reveal`, never `reveal_window` (its Q10 typing guard is for agents). `drawer-keys.test.ts` fails if `menu.rs` claims `Ctrl+digit`; ⌘1…⌘9 stay `CmdOrCtrl+N`, which is ⌘ on macOS. macOS «Switch to Desktop N» (Mission Control → Shortcuts) takes ⌃N before any app when the user has enabled it — then the key never arrives, and nothing in the app can tell.
- **The carousel and the drawer.** A hover-opened drawer does not close while the carousel is up: the carousel lies outside `.drawer-wrap`, so the pointer on its way to a thumbnail has "left" the drawer; `closeCarousel` re-schedules the hover close. While a card is dragged, every key except Esc (which cancels) is swallowed — nothing may change the query, and with it the drop target, under the card. While ⌘G's carousel is up it owns every key, except during the «got» pulse after a pick; a press off the thumbnails cancels it and gives the keys back to the list.
- **⌘G is a drawer key («В окно…»), like ⌘L/⌘R/⌘U; ⌘M is macOS Minimize** (tabs-questions Q11). `DRAWER_MOVE_KEY` in `drawer-keys.ts`; it and the selection bar's «В окно…» (tooltip ⌘G) act only inside the drawer, and outside it ⌘G stays CodeMirror's `findNext` — the editor is not touched. ⌘M is the predefined Minimize in the native Window menu (`menu.rs`), which carries the key **without an `.accelerator("…")` string**, so the accelerator mirror cannot see it. `drawer-keys.test.ts` pins both sides: it fails if `menu.rs` claims ⌘G, if the Minimize item disappears, or if a drawer key becomes ⌘M.
- **Svelte 5 attaches `onwheel` (and touch) handlers as passive**, so `preventDefault` there is ignored and the page behind scrolls. A wheel that must be taken needs `addEventListener('wheel', …, { passive: false })` in an `$effect` (`WindowCarousel.svelte`).
- **The drawer's root is `display: contents`, on purpose.** Any positioned wrapper — even `position: fixed` with no z-index — is a stacking context, and the AI button (fixed, z 880) would then paint over the whole open drawer. The scrim (850) and the drawer (900) are `position: fixed` children that stack with the button in the page's context. Consequence for tests: `.tab-drawer` is that root, *above* the handlers — a synthetic `pointermove` dispatched on it never reaches `.drawer-wrap` (hover close). Dispatch on those elements or on a card.
- **`animate:`/`in:`/`out:` cannot sit on a component.** Drawer cards are wrapped in a `.card-slot` div that carries them, and the slot owns the gap (`padding-bottom`) so the collapse animation takes the gap with it.
- **Menu actions that take the keyboard elsewhere close the drawer first** (`DRAWER_CLOSING_ACTIONS` in `App.svelte`: find, recent files, AI comment, select all, open, save as, new tab, format JSON). Anything not in the set — ⌘⇧T, Compact — runs with the drawer still open. ⌘1…⌘9 are special-cased: with the drawer open they pick the n-th *visible* card (the one whose hint reads ⌘n, D14) and then close it.
- **An agent never takes the tab the human is typing in.** "Typing" = a key without ⌘/⌃ that is not a lone modifier, into an editable element of this window, in the last 2 s, while it has focus (`lib/tabs/typing.ts`, fed by a capture-phase `keydown` in App). Arrow keys and other navigation count, and so do IME `Process` keys — deliberately on the safe side: a false "typing" only sends a command to the background. `decideLanding` then sends every command that would switch tabs to the background — `focus: true` included — and the answer says `"focused":false`. On the active tab itself nothing moves: a `show` only pulses (an off-screen target stays off-screen) and still answers `"focused":true`. `edit` and `ask` never switch tabs at all. **And app-wide (Q10):** that rule sees only its own window, so every window also reports its typing to Rust (`note_typing`, throttled to one per `TYPING_NOTE_INTERVAL_MS` = 500 ms, focused window only) and `typing.rs` keeps one last-typed window + instant. While it is fresh (`TYPING_GRACE_MS` + 500 ms — the report can lag the last key by one interval), `ai_socket::dispatch` strips `focus` from any command for *another* window or a new one (`quiet_payload`: no tab switch there, the new window built `Activation::Background`) and rewrites its answer's `focused:true` to `false` (`quiet_answer`), and `reveal_window` refuses (`false` → the frontend answers `focused:false`). The typed-in window itself is left to its per-window rule. Both constants are mirrored in `typing.ts` and a Rust test reads that file. Human paths (`reveal_other_window`, the single-instance open, `focus_if_open`) never consult it.
- **Leaving a tab parks its agent questions; nothing cancels them.** `stashActive` calls `ai.leave` before the strip, `settle` calls `ai.enter` after `tab_activate`, `closeNow`/`releaseAll` call `ai.forget`. `cancel_ai_ask` is gone. The Rust side's errors for a closed tab (`tab closed`), released tab (`tab released`) and closed window (`window closed`) are what an agent gets; the timeout counts from the request, and a question past its deadline is not shown on entry.
- **An agent's edit of a background file tab is written to disk at once** (`applyToTabNow`), so "background file tabs are always clean" still holds. Its baseline becomes the written text, so returning reuses the cached state (undo, highlight).
- **An agent's edit is told apart from a human's by its effect, not its origin.** Every agent text change carries `setAiHighlights` and is its own undo step (`aiEditTransaction`: `isolateHistory.of('full')`, or one ⌘Z takes a neighbouring keystroke with it); a reload from disk carries `addToHistory: false`. `isHumanEdit` (`editor/human-edit.ts`) is "neither" — any key, paste, format, checkbox, drop, undo — and that is what turns a quick look into «Оставить» (`tabs.humanEdited()`, synchronous and unqueued so an update listener can call it mid-command). A new kind of programmatic change must carry one of the two markers, or it will count as the human's.
- **Quick-look expiry never closes the active tab of any window**, focused or not: couplet usually sits unfocused beside the agent's terminal while the human reads it. Only background quick looks expire (clean by construction, closed the ⌘W way); an unseen one never does; the hour starts at the first view. **Persisted across a restart** (tabs-questions Q8): `transient`/`transientSeenAt` ride `tabs_sync` into `session-v2.json` like the drawer stamps (serde defaults, no version bump) and come back through `pending_tab_from_snapshot`, so the hour keeps counting from the first view before the restart — seeing it again after launch does not restart it. One that expired while the app was down is handled by the first expiry tick (≤ 1 min after launch) by the File-menu policy, background tabs only: an active restored quick look stays until it is left. ⌘⇧T still brings a closed quick look back as an ordinary tab.
- **`ai_respond` accepts an answer only from the window its request was delivered to** (`AiPending::respond_from`); it fills in `window` from the registry, over whatever the frontend sent.
- **An agent `close` is registered in `AiPending` without a path** — `tab_close`'s `cancel_for_tab` would otherwise fail the very request that closed the tab — and a window's last tab answers before the window closes (`closeTabNow`'s `onLastTab`).
- **Routing puts "the file is already open" above a live `window_binding`** (one file, one tab app-wide); a dead binding is an error even then. A window's project is bound once, lazily, from its first file (`routing::bind_missing_projects`, the directory walk outside the registry lock), and persisted in `session-v2.json`. Step 4 fills a `main` that is still as it started (no project, no file tab) before building a second window. A Finder open (`RunEvent::Opened` → `window::route_opened_file`) goes by project too (tabs-questions Q4): its own tab → a window of its project (`routing::project_window`, same rank) → a `main` still as it started (`routing::main_untouched`, the same rule as step 4) → a new window; being a human's open, the window comes forward. `open_os_files` does the routing on a blocking thread — path normalization and the project walk touch the disk — and each open on the main thread, waited for before the next file.
- **One path spelling, at every entry — the registry boundary included.** `OpenFiles` is keyed by the exact string, so `/tmp/a.md` and `/private/tmp/a.md` would be two tabs autosaving one file. `path_norm::normalize_path` runs in `resolve_path` (CLI args, pending files, single-instance argv), at the command socket's door (`request_path`, which also refuses a relative path: `path must be absolute`), in the tab commands, window opens, session restore and ⌘⇧T. `normalize_str` asks the file system — never call it under the `OpenFiles` lock. Known gap: case is not folded, and APFS is case-insensitive, so `A.md`/`a.md` are still two spellings.
- **`couplet <file>` takes two paths.** Plain, from a human: the single-instance socket, one new window with the files as tabs (`open_files_window`). With `-t`/`-b`/`-f` or `CLAUDECODE` set: the command socket (`ai open`), routed, at most 50 files. `ls` and `close` never launch the app. `/usr/local/bin/couplet` is a copy — after a CLI change, `scripts/install.sh` must be re-run, or the old copy opens a file called `ls`.
- **A window created for a background command is built with `.focused(false)` and no `NSApp activate`** (`window::build_window`, `Activation::Background`); `reveal_window` is how a `focus: true` brings an existing window forward. An `ask` is the exception: a window built for it is `Foreground` unless someone types (`ai_socket::new_window_activation`, tabs-questions Q7), and `scripts/couplet` cold-starts an `ask` with plain `open`. `focused(false)` alone makes tao `orderFront` it — over the window the human types in — so `keep_behind_key_window` orders it just below couplet's key window. It uses the `objc` runtime directly (`Class::get`, `Sel::register`, `send_message`), not `cocoa` + `msg_send!`: every `cocoa` item is deprecated and `objc` 0.2's `sel!` expands to a `cfg(feature = "cargo-clippy")` this crate does not declare, so each call would add a clippy warning. Its `BOOL` is compared with `YES`, never a `bool` literal (the x86_64 trap above).
- **Focusing a dev window without OS tools:** from its own webview, `window.__TAURI_INTERNALS__.invoke('plugin:window|set_focus', { label })` (fire-then-read — the eval times out but the call lands). `core:window:allow-set-focus` is already granted. `manage_window` has no focus action, and System Events/keystrokes are off limits. The focus change also moves `menu_route`'s last-focused target, so a following AX menu press lands in that window.
